# Подготовленные миссии

Все изучаемые сейчас миссии относятся к онборду: intro, control, wooden_hook, hook_use, canned_eat, shark_attack. hook_use остаётся в отдельном файле исполнителя, но входит в ту же группу и общий каталог. Миссия задаёт цель, порядок и критерий завершения; навык задаёт переиспользуемое действие. Движение и наведение применяются и в control, и в бою с акулой; крафт — в wooden_hook, работа крюком — в hook_use. Это отдельные понятия, не создавать копию навыка для каждого квеста. Границы одобрения навыка и миссии фиксировать отдельно.

Последовательность и инструкция координатору: [ONBOARDING_RUN.md](../../brain/agents/ONBOARDING_RUN.md), машиночитаемый порядок — [onboarding-sequence.json](../../brain/agents/onboarding-sequence.json). В текущем наборе hands_collect отложена; вызов последовательности не начинает новую игру.

Единый формат — отдельная factory подготовки, handler run/cancel и ключ mission + Unity epoch + packet revision. Импорт модулей ничего не запускает. Factory создаёт локальные bindings и параметры без обращения к Unity. Наблюдение и обязательные контроллеры инициализируются при фактическом запуске; команда компилируется при первом использовании. При повторе восстанавливаются только свежие подписки/контекст, без перечитывания истории и повторного составления команд.

Единая точка для координатора: `catalog.mjs#prepareSelectedMissions`, затем `executeSelectedMissions`. Передаются только выбранные mission/epoch/revision, уже проверенная session и локальный parameterDirectory. Каталог сам выбирает существующую factory; координатор не собирает C# и зависимости перед каждым повтором. У каждой миссии свой каталог параметров, повтор использует уже готовый handler.

Точки подготовки в `onboarding-runner.mjs`: `prepareIntroMission`, `prepareControlMission`, `prepareWoodenHookMission`, `prepareSharkAttackMission`. Эталонный `prepareHookMission` остаётся в `hook-runner.mjs`.

С 29.10.2026 по прямому решению человека рабочий цикл выполняет только нужные для задачи команды. `qa.prepareMissions(ids)` только сверяет текущий контекст и регистрирует handlers, без пробных UI-сессий и предварительной компиляции. Затем `qa.runPipeline` начинает обычное выполнение. Fresh observer, error watcher, ownership, отмена и cleanup сохранены. Для shark_attack необходимые боевые delegates устанавливаются внутри фактического запуска миссии под теми же stop/error guards; это создание рабочего контроллера, не предварительный прогон его команд.

- intro: Next по текущим страницам, затем Finish, свежий Done до перехода дальше. Левое смещение уже есть в проверенном selected-control.
- control: движение, затем Look. Учитываются свежие этапы и реальные изменение позиции/поворота; жесты ограничены и отпускаются.
- wooden_hook: штатный крафт выбранного квестом рецепта, закрытие Craft, свежий Done. Успешно отправленный Create не дублируется.
- shark_attack: Quests → миссия → закрытие панели/диалога → прежняя защита крюком → свежие retreat и Done. Пассивная защита и полная миссия — разные пакеты. По умолчанию ни новой игры, ни дополнительного dev-вызова атаки нет.

`MissionPool.readiness` показывает наличие реального handler в текущем процессе для нужной эпохи/ревизии. Текстовый `dispatch.py --prepare` этого не делает. `getMissionPool()` даёт постоянную точку доступа, чтобы после сжатия контекста не искать прежние имена переменных REPL. После сброса процесса пул нужно подготовить заново.

`runMissionSequence` до первого запуска проверяет готовность всех выбранных handlers. Миссии идут последовательно; NEEDS_REVIEW или стоп не позволяют перейти к следующей. Только один исполнитель владеет вводом. После подготовки другого handler собственные локальные параметры привязываются заново — соседняя миссия не должна перехватить файловые настройки предыдущей.

В отчёте различать:

1. Пакет найден в памяти.
2. Код/обвязка проверены офлайн.
3. Команды действительно подготовлены в текущем Unity.
4. Миссия прошла live с нужной скоростью и подтверждённым результатом.

27.10: control и wooden_hook прошли новой обвязкой за 7.393/7.612 с вместе с запуском через чит-панель; свежие Done, ошибок нет, скорость одобрена человеком. intro остановился при замене Next на Finish; после подсказки Finish нажата, окно закрылось. Исправлено быстрое переключение цели при доказанном отсутствии ввода, тесты прошли; автономный повтор после исправления ещё нужен. shark_attack новой обвязкой здесь не запускался. Старый успешный прогон не заменяет проверку новой реализации.

## Очередь с параллельной подготовкой, 28.10

Основной составной запуск теперь `tools/portable/runtime.mjs#runPipeline`; `runMissions` — alias. [PIPELINE.md](../../brain/agents/PIPELINE.md) описывает подготовку следующих двух пакетов без MCP во время активной миссии, одного владельца ввода и baseline ошибок на весь цикл, непрерывный журнал и общий анализ после цикла. Handlers регистрируются локально; Unity-команды вызываются только по мере выполнения. Переход требует свежего результата и остановки ввода; поздние callbacks завершённой миссии отклоняются. Предложения знаний не меняют активные версии. Новая обвязка проверена только офлайн, игровой прогон ещё нужен. Прежние runMissionSequence/executeSelectedMissions оставлены для совместимости и не дают этих гарантий конвейера.
