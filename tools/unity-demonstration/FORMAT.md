# Demonstration log v1

Implementation contract shared by Unity recorder and offline analyzer. All timings are frame-observed, not OS hardware event timestamps. No global keyboard hook, text capture or gameplay control.

Session folder contains `session.json` metadata and `events.ndjson` (one JSON object per line), plus optional `video.mp4`. `session.json` records schema `ocean-demo/1`, session_id, start_utc, profile_id `ocean-nomad-editor-v1`, game/unity version, frame sampling policy and completion/IO status. Current default output is a sibling `<project-name>-qa-demonstrations` directory outside the game's Temp and Git. The Editor video adapter uses official Unity Recorder 5.1.7; earlier sessions without video remain valid action logs.

Every event has `schema`, `session_id`, integer monotonic `seq`, `kind`, Unity `frame`, monotonic elapsed `t_ms` (milliseconds from recorder start, excludes neither pause nor lost focus), `utc`, and `data`. Sequence and elapsed time must not go backwards. Final line may be incomplete after a crash; report it, do not silently claim a complete recording.

Kinds:

- `session_start`: profile and timing origin.
- `input`: `keys_held`, `keys_down`, `keys_up` arrays of whitelisted Unity KeyCode names; `mouse_held`, `mouse_down`, `mouse_up` arrays of button indices; `mouse_position`, `mouse_delta`, `mouse_scroll` two-number arrays; `axes` map of axis name to `{available, value}`; `focused`, `capture_allowed`, `suppressed_reason`; `ui_hit` object path on pointer transitions if known, otherwise null. Input sampled every Update, emitted on edges/changes/nonzero motion or a 100 ms heartbeat. Held values are state; only down/up are observed edges.
- `state`: `player` null if unavailable, otherwise `{instance_id, scene, position:[x,y,z], rotation:[x,y,z,w], grounded:bool, parent_id, local_position:[x,y,z]}`; `camera` null or `{position, forward, source}`; `game_signals` null or axes read from the game's already-existing JoysPlayerSettings. Do not infer that command was consumed. Sampled in LateUpdate at up to 10 Hz, plus grounded transitions and the next LateUpdate after a marker. Coordinate units are `unity_units`, not assumed metres. Runtime identity does not persist between sessions. State samples are correlated by frame/time; no claim of exact internal input consumption order.
- `gap_start` / `gap_end`: `reason` e.g. `focus_lost`, `game_view_not_focused`, `text_input_selected`, `editor_paused`. A gap interrupts held intervals; never fabricate a key-up during a gap.
- `scene`: loaded/unloaded scene name and path; world identity may change.
- `marker`: `label`, marker_id. F8 means user sync marker; label does not count as quest success.
- `video`: optional status event (`recording`, `file_written`, `failed`, `disabled`) with request, fixed relative filename video.mp4, source GameView, audio=false, Variable frame rate, target_fps=30, start-call/start/stop/finalize elapsed times and Unity start frame, size/error. Final video status is also in metadata under `video`, with `video_recorded` true only after a nonempty file has been finalized. Journal completion and video success are separate. Absent/failed requested video makes combined analysis fail; file presence does not prove valid contents.
- `session_end`: reason, samples/events and writer status `pending_flush`. Actual flush is recorded afterwards in `session.json`: `finalized:true`, `complete:true`, no `writer_error`, matching `events_accepted`/`events_written`. An end event alone never proves completion. A complete journal may still contain focus gaps and does not prove any gameplay outcome.

Key whitelist: W,A,S,D, UpArrow,DownArrow,LeftArrow,RightArrow, Space, LeftShift,RightShift, LeftControl,RightControl, LeftAlt,RightAlt, Escape, F8. Mouse buttons 0,1,2. No Input.inputString, unrestricted key scan, device identifiers, account values or text fields. Capture only while application and Game View are focused and no editable uGUI/TMP field is selected. Suppress raw input on pause/focus loss; annotate gaps. Game state is read-only.

Profile evidence: the user explicitly confirmed on 2026-10-21 that Space triggers jump. Raw Space down records jump intent; only observed game state can corroborate takeoff/landing. A state change alone does not prove which key caused it.

Current default video profile is LogicLight: maximum 960×540 preserving aspect/even dimensions, Low encoder quality, variable capture every third frame with game target 30 (nominal video 10 fps). Full input sampling remains each Update. Input includes optional screen_size and mouse_position_normalized; raw mouse_position remains Game View pixels. Optional temporary Fastest quality/FPS/VSync/resolution overrides are restored on Stop and recorded under video profile/prior/environment_restored fields. submitted_frames is the Recorder submission count, not proof of encoded frame validity. update_timing records observed Update cadence (including stalls), not GPU time or comparative speedup. Earlier Original-profile sessions remain valid with their recorded settings.

Analyzer output should include input coverage/gaps, hold intervals with start/end observed vs interrupted/truncated, simultaneous key chords, mouse button holds, markers and frame-matched state context. Grounded→airborne→grounded transitions are candidates, not automatic successful jumps; attribute an input only within an explicit temporal window and preserve ambiguity. No session yet counts as a real demonstration merely because a synthetic fixture passes tests.

Video and journal start from one UI operation, not an asserted identical first encoded frame. Video uses Unity simulation timestamps; journal t_ms includes real pauses and stalls. Match video pixels' overlay t_ms/frame/marker to events, rather than assuming MP4 presentation seconds equal journal elapsed seconds. Earlier action-only session 20261021T130518Z-8901a7b9 was human capture; technical empty-scene validation videos are not game evidence.

## UPM recorder 0.1.0 extensions

Package0.1.0 preserves ocean-demo/1. Optional session metadata package_id/package_version identify the recorder. Profile is selected per session: ocean-nomad-editor-v1 when its adapter is available; unity-editor-generic-v1 otherwise, with unknown jump binding and null game state. Ocean-specific input interpretation must not be assumed for another profile. Earlier sessions remain readable.

- kind=module: data={module_id,event_name,payload}. Same seq/frame/t_ms origin; payload interpretation belongs to the module. Inventory/quest telemetry is not implemented in0.1.0.
- kind=module_error: callback phase and error_type; also session.json.extension_errors. Analyzer reports an error even if the journal itself is complete. Full journal does not assert extension/gameplay success. No exception messages, private game values or stack traces are recorded by this fault handler.

## Ocean quest/world module — package0.2.0

Module ID ocean.quest-world automatically participates in Ocean Nomad capture. Initial/final snapshots plus changed samples up to5Hz,2s heartbeat; source/component-list discovery at most1Hz. It is sampled telemetry, not a lossless quest/action event stream. It never calls Resolve, Fire, pickup or movement/camera setters.

- quest_snapshot payload: availability/source/error/loaded; tracked_quest_uid; active_quests and active steps with type/value/need/is_complete/target_uids; active_collect_target_uids and bounded observed_collect_target_uids. UID-only parameter extraction excludes passwords/text. History-completed IDs are limited to quests observed in the session; membership is not proof of a new completion. Missing manager/contract gives unknown/unsupported and null, not a fabricated empty quest list.
- spatial_snapshot payload: scope/query_status; unity_units; player world/parent frame and transform; actual camera position/forward when available; matching loaded Pickable objects with UID/runtime instance/QuestObject saved ID, scene path/handle, world/own-parent/player-parent positions, active/enabled/taken/CanPickup flags, collider-centre or transform-fallback aim point. Distances and yaw/elevation refer to the aim point; yaw positive right, elevation positive up. These are geometric errors, not calibrated input-axis values.
- World matching currently supports ObjectCollect with explicit UID parameters. Other objective types remain in quest data but are not resolved as pickables. Limits:16quests,32steps/UIDs-per-step/recorded-targets,64observed quest/object IDs,4096candidate components and512history records; truncation/limit flags signal incomplete coverage. All positions are live session observations, not persistent routes.
- visible/reachable/selected_pickup_target remain null; path_status=not_evaluated. No surface, obstacle, safe-path, automatic look or inventory-reward verification is implemented. Coordinates cover loaded scenes, not the global map/unloaded islands. Empty lists are not global absence claims. Nearby query without player returns player_unknown.

ReadSnapshot() and ReadNearby(radius,limit) are read-only adapter methods usable through MCP execute_code, not new native tools. They do not start a recording. Analyzer quest_world_telemetry indexes latest module samples by seq/time and bounded quest/target identifiers/positions; completion stays not_inferred. Old sessions get status=not_recorded. Full snapshots remain in events.ndjson.
