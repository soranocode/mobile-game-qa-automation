# Запись управления в Unity Editor

Рекордер демонстраций (с 23.10.2026 отдельный [UPM-пакет com.gameqa.demonstrations 0.2.0](../../packages/com.gameqa.demonstrations/README.md)): **одной кнопкой записывает видео Game View и журнал управления в одну папку**. Он не нажимает игровые кнопки, не запускает Play и не проходит квесты. Исходники предназначены только для Editor (`#if UNITY_EDITOR`). Видео обеспечивает официальный Unity Recorder 5.1.7.

## Первая демонстрация

1. Вручную войти в Play, открыть нужный игровой участок и снять паузу.
2. Открыть **Window → QA → Demonstration Recorder**. В `Session goal` кратко написать цель, например «движение и прыжок».
3. Оставить включёнными **Record video (Game View)**, **Timecode overlay**, **Light recording (540p / ~10fps)** и **Low graphics while recording**.
4. Нажать **Start video + actions**. Фокус автоматически перейдёт в Game View; на экране появятся таймкод и номер кадра. **F8** добавляет дополнительный маркер по желанию.
5. Выполнить короткую демонстрацию: движение, остановка, поворот, прыжок через Space. Для первого опыта достаточно 30–60 секунд. Затем открыть окно рекордера и нажать **Stop and save**. Кнопка **Open session folder** откроет результат.
6. Сообщить цель и объяснить действия по порядку; если есть видео, указать маркеры. Сначала проверяем, что ввод и состояние записаны правильно, затем извлекаем опыт.

По умолчанию используется папка **<имя проекта>-qa-demonstrations** рядом с каталогом игрового проекта, вне его Temp и Git. Например, для каталога `raft` — соседний `raft-qa-demonstrations`. Старое стандартное значение Temp/QaDemonstrations автоматически заменено; явно выбранные другие пути сохранены. Путь виден в `Local output root`.

Каждая сессия имеет отдельный каталог: **video.mp4**, **session.json**, **events.ndjson**. Видео — H.264 MP4 без звука/микрофона. Новый стандартный профиль **LogicLight** уменьшает Game View до 960×540 максимум с сохранением пропорций и чётных размеров, использует низкое качество кодирования и захватывает каждый третий кадр при ориентире 30 игровых обновлений/с (около 10 кадров видео/с). Ввод по-прежнему опрашивается каждый Update; прореживаются только картинки. Для пиксельных координат мыши сохраняются размер экрана и нормализованная позиция.

**Low graphics while recording** временно включает уровень Fastest (в данном проекте без теней/сглаживания, с уменьшенными текстурами). После остановки восстанавливаются прежние качество, лимит FPS, VSync и размер/выбор Game View. Инициализация сцен может переустанавливать настройки; активный профиль повторно применяется не чаще раза в секунду. Настройки и факт восстановления сохраняются в метаданных. Этот профиль предназначен для обучения последовательности действий; графику/производительность обычного билда проверять отдельно на нужных исходных настройках.

Чтобы записывать прежним способом, снять Light recording: исходный размер Game View, High, ориентир 30 fps. Можно снять галочку видео и записать только действия. Первая пользовательская сессия до интеграции не содержит видео. Вторая человеческая сессия 20261021T133657Z-38311f33 содержала сильные задержки и не сохранила MP4; её журнал цел, она не считается успешной совместной записью.

При обычной остановке и выходе из Play сначала завершается видео, затем сбрасывается журнал. Не закрывать Unity принудительно до окончания сохранения. При сбое запуска/остановки видео окно показывает ошибку; журнал и статус видео проверяются отдельно. Наличие непустого MP4 ещё не является проверкой его содержимого.

В окне во время записи показан Update cadence, в session.json — update_timing с наблюдаемой средней частотой Update и наибольшим интервалом. Это включает загрузочные задержки и не является GPU-профилированием или сравнением с запуском без рекордера. В метаданных видео также есть submitted_frames; это счётчик переданных кадров Recorder, а не подтверждение их декодирования. Отсутствие первых видеокадров при продолжающихся игровых обновлениях приводит к явной остановке с ошибкой.

При потере фокуса, выборе текстового поля или паузе ввод пропускается с явной отметкой. Клик по окну рекордера тоже создаёт такой пропуск. Удержание во время пропуска не превращается в вымышленный key-up. Состояние игрока может отсутствовать в меню или при неоднозначном источнике; это неизвестное значение.

## Что фиксируется

- Нажатие, отпускание и удержание разрешённых клавиш, сочетания; кнопки, положение и перемещение мыши; игровые оси.
- Время и кадр Unity, сцены, синхромаркеры F8, пропуски наблюдения.
- При наличии единственного активного `Survival.Views.Movement`: положение и вращение игрока, родитель и локальная позиция, `Grounded`, положение и направление камеры. Читаются уже существующие объекты; игровые сервисы не создаются.
- Уже загруженные сигналы `JoysPlayerSettings`, если источник однозначен. Это снимок значений, без доказательства потребления ввода игрой.

**Space = прыжок** подтверждено пользователем 21.10.2026; в исходниках `HudControlsManager.LateStep` читает ось `Jump`, связанную с `space` в InputManager. Само нажатие подтверждает намерение; отрыв и приземление проверяются по состоянию. Геометрия мира, враги и квесты пока не классифицируются.

## Установка на другом ПК

После клонирования automation-репозитория остановить Play и запись. В Unity Package Manager выбрать Install/Add package from disk и указать packages/com.gameqa.demonstrations/package.json. Зависимости Recorder5.1.7, Newtonsoft.Json3.2.1 и Unity UI2.0.0 объявлены самим пакетом. Минимальная версия Unity6000.0. Из корня automation-репозитория также доступен установщик:

~~~text
python tools/unity-demonstration/install_recorder.py --project PATH_TO_GAME
python tools/unity-demonstration/install_recorder.py --project PATH_TO_GAME --apply
python tools/unity-demonstration/install_recorder.py --project PATH_TO_GAME --apply --migrate-legacy
~~~

Первая команда показывает план. Вторая подключает локальный пакет одной зависимостью в Packages/manifest.json. Третья нужна при наличии прежней установки Assets/QaDemonstrations: сначала создаёт резервную копию, затем убирает только старые C# и .meta с известными SHA256. Сцены и другие ассеты остаются на месте; неизвестные/изменённые скрипты блокируют миграцию. Старую и пакетную копии одновременно держать нельзя. Установщик сам не останавливает Play — это предварительное условие.

Резервные копии: Library/GameQaDemonstrations/Migrations/<timestamp>/, файлы manifest.json.before и legacy/. Для ручного восстановления закрыть Editor, вернуть manifest.json.before как Packages/manifest.json и файлы из legacy/ на прежние пути Assets/QaDemonstrations, затем открыть проект. Если после миграции менялись другие зависимости или старые файлы, сначала сопоставить изменения; не перезаписывать их старой копией вслепую. Полный manifest/backup могут содержать приватные URL — в automation Git их не добавлять.

После подключения выполнить Assets → Refresh и дождаться компиляции. На новом ПК или в другой копии игры подключение повторяется: локальная ссылка требует наличия checkout пакета. Код пакета хранится отдельно от игровых исходников. Git clone automation-репозитория не устанавливает Unity, игру и её приватные зависимости. Git URL с pin на commit/tag можно использовать после публикации; локальная установка не означает commit/push.

Проверки: python -m unittest discover -s tools/unity-demonstration -p "test_*.py". Синтетические проекты проверяют резервные копии, отказ при неизвестных файлах, откат и повторную установку. В этой папке остаются Python-инструменты/документация; единственный источник C# теперь packages/com.gameqa.demonstrations. Контракт будущих модулей описан в README пакета; инвентарь пока не записывается; квесты/целевые предметы и координаты теперь пишет модуль ocean.quest-world0.2.0.

## Анализ завершённой записи

```text
python tools/unity-demonstration/analyze_demo.py SESSION_FOLDER --output LOCAL_SUMMARY_FOLDER
python tools/unity-demonstration/test_analyze_demo.py -v
```

Анализатор работает офлайн, без API и запросов к модели на каждом кадре. Он выдаёт удержания, парные сочетания, пропуски, маркеры, перемещения и кандидаты на прыжок. Мировое перемещение включает движение плота и не равно дистанции ходьбы. Итог требует человеческого разбора; автоматической записи навыков в память пока нет.

**Синхронизация:** видео содержит время журнала и Unity frame. Старт обеих записей общий, но первая кодированная картинка не обязана совпасть с вызовом Start. Unity Recorder использует время симуляции, журнал — монотонное реальное время. Паузы, подготовка кодека и загрузочные задержки могут давать разную длительность файлов; совмещать по видимым таймкодам/кадрам, а не приравнивать секунду MP4 к секунде журнала. FPS и нагрузка при реальном игровом переходе ещё требуют проверки.

Контракт данных: [FORMAT.md](FORMAT.md). Подробности анализа: [ANALYZER.md](ANALYZER.md). Проверки и ограничения: [VERIFICATION.md](VERIFICATION.md).

Изменения этого этапа пока локальные.
