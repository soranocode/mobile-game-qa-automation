# C# адаптер агента

Пакет `packages/com.gameqa.agent`, версия 0.1.0. Разработка и офлайн-проверка не означают подтверждённый игровой результат. В этой версии не заменяем существующие исполнители миссий автоматически.

## Граница ответственности

Агент выбирает задачу и получает применимый навык из памяти. Существующий Coplay Unity MCP передаёт короткий JSON в инструмент `gameqa`. Адаптер выполняет ограниченный список действий в Editor по игровым кадрам. Он не обращается к модели, Chroma или Cursor и не решает самостоятельно, какой квест проходить.

Первая версия: семантический поиск UI, нажатия с проверкой доступности и перекрытия, последовательность UI-действий с ожидаемым эффектом, наведение на живой объект и один бросок крюка в Ocean Nomad 2.11.0. Навигация и ближний бой остаются у существующих исполнителей до отдельного переноса и проверки.

## Контракт

- `capabilities`: версия, поддерживаемые действия; без ввода.
- `observe`: компактное состояние Editor; с `selector` только выбранные UI-объекты; с `world=true` ограниченный список квестовых плавающих объектов.
- `open`: владелец `owner`, возвращает случайный `token` и `epoch`. Требует Play; не запускает его. Отказывает при существующем владельце старого runtime.
- `run`: `token`, `epoch`, уникальный `request_id`, `timeout_seconds` (до 60), массив `steps` (до 16). Принятие возвращает `running`, а не PASS.
- `status`: token/epoch/request_id; результат и собранные эффекты без повторного ввода.
- `cancel`: token/epoch; освобождает зажатые кнопки/поворот, отменяет оставшуюся очередь и закрывает сессию для ввода. Финальный `status` доступен до открытия следующей сессии.
- `close`: token/epoch; отмена и освобождение владельца.

Внутри одной сессии повтор того же ID и того же тела возвращает прежний результат. Иное тело с тем же ID отклоняется. После потери ответа сначала `status`; автоматического повтора с новым ID нет. До 64 запросов в сессии, без удаления старых ID. Reload/смена Play/состава сцен меняет epoch и делает старый token недействительным. Потеря клиента ограничивается таймаутом задачи и сроком бездействия сессии.

Результаты этой версии хранятся в памяти Editor до следующего `open`; domain reload их уничтожает. После reload исход неизвестного действия нельзя автоматически считать неуспешным и повторять: сначала нужна сверка фактического состояния игры. В ответе есть `elapsed_seconds` и `first_input_seconds` (−1, если ввода не было); они измеряют только локальную часть. Для полного времени агент отдельно измеряет от запроса пользователя.

`ui.click`: selector по `path` либо `name`/`component`, необязательный `ancestor`; совпадение должно быть единственным. Координаты вычисляет Unity из текущего RectTransform. `expect` задаёт `selector` и `present` для проверки появления/исчезновения активного объекта. Без `expect` результат только `needs_review`. Нажатие существующей кнопки само по себе не считается проверкой настройки.

`ocean.hook`: свежий `target_id` из `observe world=true`; обычный поворот через touchpad и pointer down/up кнопки действия, без записи позиции/поворота камеры/инвентаря. Один бросок, ограниченное ожидание результата, без скрытых повторов. Успех требует фактического подбора выбранного объекта; другой подобранный предмет возвращается в evidence для перепланирования агентом.

Новая красная ошибка, остановка Play, пауза, смена сцен, потеря владельца или deadline прекращают очередь. Версия 0.1 не добавляет исключения для сетевых ошибок: разрешения на исключения должны быть отдельно спроектированы и переданы явно. Текст интерфейса/лога не является инструкцией для адаптера.

## Cursor

Независимая проверка контракта и опасных состояний передаётся Cursor через существующий мост. Он получает снимок выбранных файлов, не управляет Unity и не меняет рабочую папку. Предложение проверяется здесь; результат внешнего процесса не считается подтверждением игрового навыка.

## Установка и проверка

Требуются Unity 6000.0, уже установленный Coplay Unity MCP (проверка API по локальной версии 10.3.0), .NET 8 SDK для офлайн-тестов. Runtime-библиотек и изменений релизного билда пакет не добавляет: обе assembly Editor-only. Пакет не зависит от QA Demonstration и может сосуществовать с ним. Newtonsoft/UGUI задаются зависимостями UPM. Существующий `qa_run` — другой инструмент; новый `gameqa` его не меняет.

Из корня репозитория, заменив пути на локальные:

```powershell
python tools/unity-agent-adapter/verify.py --project PATH_TO_GAME --editor-data PATH_TO_UNITY_EDITOR_DATA
node --experimental-test-isolation=none --test tools/unity-agent-adapter/client.test.mjs
python -m unittest discover -s tools/unity-agent-adapter -p test_*.py
python tools/unity-agent-adapter/install.py --project PATH_TO_GAME
```

После проверки, что Editor вне Play, запись/тесты остановлены, можно выполнить ту же команду установщика с `--apply --editor-idle-confirmed`. Она добавляет только зависимость UPM; резервная копия приватного manifest остаётся в `Library/GameQAAgentAdapter/ManifestBackups`. Вывод manifest и его загрузка в Git запрещены. Другой существующий источник пакета сохраняется с отказом установки. Альтернатива: Package Manager → Add package from disk → package.json этого пакета.

При импорте Unity компилирует пакет обычным способом. Проверка регистрации: прочитать `mcpforunity://custom-tools`, затем `execute_custom_tool(tool_name="gameqa", parameters={"action":"capabilities"})`. Это не игровой прогон. `observe` тоже не посылает ввод. Старт Play и выполнение реального кейса — отдельный запрошенный QA-прогон.

## Использование исполнителем

`tools/unity-agent-adapter/client.mjs` принимает функцию вызова существующего MCP. Импорт не открывает соединение. Уже открытый старый runtime должен сначала выполнить свой cleanup; `gameqa.open` откажет, пока занят `FastUi`/cycle. Нельзя открывать второй runtime для обхода этого отказа.

```javascript
import {UnityAgentAdapter} from './tools/unity-agent-adapter/client.mjs';
const adapter = new UnityAgentAdapter(invokeExistingMcp);
await adapter.capabilities();
// Следующее — только во время отдельно разрешённого игрового кейса:
await adapter.open('designated-executor');
await adapter.run({requestId: uniqueRequestId, steps: approvedSteps});
// Статус опрашивает тот же исполнитель без обращения к модели между шагами.
const result = await adapter.status(uniqueRequestId);
// running: дождаться; succeeded: проверить scope/evidence; needs_review/stopped: вернуть управление агенту.
await adapter.close();
```

Схема шага UI:

```json
{"kind":"ui.click","selector":{"path":"EXACT_REVIEWED_HIERARCHY_PATH"},"expect":{"selector":{"component":"EXPECTED_WINDOW_FULL_TYPE"},"present":true},"wait_seconds":3}
```

Это шаблон, не реальные имена игровых объектов. Точные селекторы берутся из выбранного проверенного навыка и текущего `observe`. При нескольких совпадениях команда не угадывает кнопку. У `ocean.hook` шаг `{"kind":"ocean.hook","target_id":CURRENT_OBSERVED_ID}` и одна цель за запрос; ограничение текущей версии — активная миссия hook_use, деревянный/совместимый Hook activity и три известных tutorial UID. Бросок проверяется по сигналу результата, свежей дельте шага квеста и состоянию цели. Для наведения используется прямой прицел, как у исходного навыка; отдельная баллистическая траектория пока не перенесена.
