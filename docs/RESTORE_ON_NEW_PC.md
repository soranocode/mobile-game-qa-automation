# Восстановление Unity автотестов на другом ПК

Комплект переносит код и отобранный опыт Ocean Nomad на 28.10.2026. Новый Codex работает с этим справочником и готовыми исполнителями. Состояние его чата, текущего мира и прогретых процессов создаётся заново.

## Получить комплект

```powershell
git clone --branch docs/game-brain-architecture https://github.com/soranocode/mobile-game-qa-automation.git
cd mobile-game-qa-automation
python tools/portable/bootstrap.py check
```

Если копия уже есть, сначала проверить `git status`, сохранить свою работу, затем `git fetch origin`, переключиться на указанную ветку и выполнить `git pull --ff-only`. Не стирать локальные изменения. Офлайн проверка создаёт только локальные пакеты в `brain-store/`.

На Windows выбирать короткий каталог для клона: глубокая вложенность вместе с именами тестовых кешей может превысить системный лимит пути.

## Подготовить компьютер и игру

- Установить Codex и войти в свой аккаунт. Открыть корень репозитория автоматизации как доверенный проект.
- Нужны Git, Python 3.12 и Node 24 или новее. Контрольные версии исходной среды указаны в `config/portable-release.json`. Основные Python инструменты работают на стандартной библиотеке; для необязательной картинки карты требуется Pillow. Рисовать карту для прохождения не нужно.
- Подготовить отдельную компилирующуюся копию Unity проекта Ocean Nomad 2.11.0 dev с доступом к его зависимостям и лицензией Unity 6000.0.66f2. Проверенная ветка и исходный commit указаны в release профиле. Игровые исходники и приватные зависимости не копируются из репозитория автоматизации.
- Дождаться импорта проекта и устранить ошибки компиляции. Другая версия игры требует проверки совместимости; автоматизация не подменяет настройку игрового проекта.

## Подключить Unity пакеты

В Unity Package Manager подключить MCP for Unity 10.3.0. Зафиксированная исходная ревизия:

```text
https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#aa5fc638d623f56178d50329d9ad8c541a57fe66
```

В окне MCP установить предлагаемые зависимости Python/uv, выбрать HTTP Local и поднять локальный сервер. В Unity указывается `http://127.0.0.1:8080`; клиентский MCP endpoint — `http://127.0.0.1:8080/mcp`. Для этого профиля работает только локальное соединение без секретов в URL.

При остановленных Play и записи подключить рекордер и адаптер телеметрии:

```powershell
python tools/unity-demonstration/install_recorder.py --project "ПОЛНЫЙ_ПУТЬ_К_ИГРЕ"
python tools/unity-demonstration/install_recorder.py --project "ПОЛНЫЙ_ПУТЬ_К_ИГРЕ" --apply
```

Первая команда показывает план, вторая подключает пакет. Unity подтянет объявленные зависимости Recorder 5.1.7, Newtonsoft.Json 3.2.1 и Unity UI 2.0.0. Дождаться компиляции. Этот пакет нужен и для наблюдателя hook_use, даже если видео записывать не планируется. Старую копию рекордера в Assets не дублировать; миграция описана в `tools/unity-demonstration/README.md`.

## Привязать локальные пути

```powershell
python tools/portable/bootstrap.py init --game-project "ПОЛНЫЙ_ПУТЬ_К_ИГРЕ"
python tools/portable/bootstrap.py check --local
python tools/portable/verify_offline.py
```

`qa.local.json` содержит только путь проекта и адрес локального сервера и не публикуется. Повторный init отказывается его перезаписывать без `--replace`. `check --local` проверяет пути, версию Editor и наличие зависимости рекордера, но не подтверждает связь MCP, компиляцию игры или успешность теста.

## Подключить Codex

В `.codex/config.toml` сохранён проектный адрес Unity MCP. Если экземпляр Codex уже открыт, перечитать конфигурацию/перезапустить чат по обычному порядку клиента. При другом порте поправить проектную конфигурацию и `qa.local.json` согласованно. Не переносить чужой глобальный профиль, токены или разрешения.

Проектные роли лежат в `.codex/agents/`. Они наследуют подключение и разрешения родителя; их наличие не создаёт отдельную песочницу. Для знакомой задачи дополнительный агент обычно не нужен. Основание формата — [OpenAI Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) и [OpenAI Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference).

Новый Codex начинает с `AGENTS.md` и `docs/AGENT_HANDOFF.md`. После явного запроса подключиться к редактору один раз создаёт runtime в постоянном Node REPL:

```js
var {pathToFileURL} = await import('node:url');
var portable = await import(pathToFileURL(ABSOLUTE_REPO_PATH + '/tools/portable/runtime.mjs').href);
var qa = await portable.openRuntime();
```

`ABSOLUTE_REPO_PATH` задаётся из текущего workspace, не из старой переписки. Импорт ничего не запускает. `openRuntime` проверяет выбранный Unity проект и свободного владельца ввода, но не включает Play, не меняет сцену и не запускает миссии. При недоступном сервере сначала исправить подключение.

## Восстановить готовность навыков

По команде QA войти в нужный игровой контекст. Для уже изученных миссий в запущенной и неприостановленной сцене Game подготовить по одной:

```js
await qa.prepareMissions(['intro']);
await qa.prepareMissions(['control']);
await qa.prepareMissions(['wooden_hook']);
await qa.prepareMissions(['hook_use']);
await qa.prepareMissions(['shark_attack']);
```

Подготовка не выполняет миссии и не создаёт новую игру. Первый прогрев разделить на отдельные запросы с достаточным timeout, иначе сброс REPL уничтожит процесс. Повтор при совпадающих ревизиях и эпохе использует готовый пул. После обновления исходников нужен новый idle runtime/процесс, а не старый ES module cache.

Только по новому запросу QA:

```js
var result = await qa.runPipeline({
  missions: ['intro','control','wooden_hook','hook_use','shark_attack'],
  taskId: 'human-onboarding-' + Date.now(),
  authorized: true
});
nodeRepl.write(result);
```

Во время миссии готовятся следующие два пакета без MCP; `runMissions` — alias конвейера. На весь цикл сохраняются один владелец ввода и baseline ошибок. Журнал пишется в процессе, общий анализ и предложения знаний сохраняются после цикла. Новая обвязка проверена офлайн, игровой замер ещё нужен. Детали — `brain/agents/PIPELINE.md`.

Для всей цепочки timeout должен учитывать суммарные бюджеты; внешнюю ячейку можно ожидать через running cell ID короткими интервалами. Не запускать дубликат из-за отсутствия немедленного ответа. Отмена — `qa.stop()`/AbortSignal; при неизвестном исходе сначала отмена владельца и свежее состояние. Если `cleanup_confirmed: false`, после восстановления связи выполнить `qa.recoverStoppedCycle()`; он только подтверждает остановку, без повторения игры. Детали запуска — `brain/agents/ONBOARDING_RUN.md`.

Для настроек использовать `await qa.session.prepare()`, затем `var settings = await qa.createSettingsAdapter(); await settings.prepare();` и прежний `runApprovedUiSkill`/`runApprovedSettingsChecks`. Для навигации и боя — их существующие точки подготовки в `projects/ocean-nomad/tools/`. Полная карта, позиции, активное оружие, ID целей и сигналы угроз всегда получаются заново.

## Проверить перенос

Успешный bootstrap означает комплектность и совместимость сохранённых знаний. Следующий отдельный шаг — короткая проверка связи, доступности адаптера и один разрешённый игровой кейс. Заново проходить всё обучение не требуется, но неподтверждённый перенос не помечается PASS заранее.

Git не переносит лицензию/игру, рабочие кеши, прогресс игрока, видео и полный контекст чата. В карточках остаются отобранные факты, вмешательства и статусы подтверждения; ссылки на старые локальные доказательства могут отсутствовать на новом ПК.
