# Локальная память с Chroma

Область первого варианта: карточки Ocean Nomad из `projects/ocean-nomad/knowledge/index.json`. Поиск помогает найти знания; игровые действия выполняются через существующие навыки и проверенные пакеты. Статус реализации — экспериментальный поиск для координатора, без автоматического выбора и запуска миссий.

## Что хранится и как это работает

Карточка содержит обычный текст: назначение навыка, условия, ограничения, источник и результат проверки. Embedding-модель переводит фрагмент текста в числовой вектор. В нашем варианте в нём 384 числа, описывающих смысл текста. Вектор запроса сравнивается с сохранёнными векторами, и Chroma возвращает похожие фрагменты вместе с метаданными.

Путь запроса: цель человека → точный UID/алиас или смысловой поиск → несколько карточек → проверка источников и применимости → короткий пакет координатору → существующий навык. Языковая модель получает отобранный контекст и отвечает/планирует с его учётом. Сам поиск не вызывает Unity и не меняет сохранение.

Числовые векторы текста относятся к смысловому поиску. Положение игрока, предметов, угроз и актуальный игровой прогресс берутся из текущего наблюдения Unity и не восстанавливаются из старого поискового результата.

Исходная структура памяти сохраняется: миссии ссылаются на навыки; правила и эпизоды имеют владельцев, статусы и источники. Именно эта структура позволяет ограничивать выборку. Полные чаты, видео, сырые логи и игровые ассеты в первый индекс не входят. Архитектурные документы и код при необходимости следует добавить отдельной коллекцией, с собственной областью поиска.

## Компоненты

- Chroma 1.5.9 через PersistentClient: локальные векторы, документы и метаданные.
- FastEmbed 0.9.1 и CPU ONNX Runtime: многоязычная `paraphrase-multilingual-MiniLM-L12-v2`, два CPU-потока, без GPU и embedding API.
- Публичный ONNX-снимок модели зафиксирован по revision в `config/rag.json`. Поиск использует только локальный кеш; загрузка разрешена при явном `sync`.
- Сначала разбиение по разделам Markdown, затем по реальному лимиту токенизатора с перекрытием. У этой модели лимит 128 токенов; молчаливое обрезание не допускается.
- Точные UID/алиасы идут по прямому пути и не загружают модель или Chroma. Остальные запросы используют векторы и ранги существующего поиска по метаданным. `--semantic-only` отключает эти подсказки для проверки векторной части.

## Установка и использование

Из корня репозитория на Windows / Python 3.12:

```powershell
python -m venv work/rag-venv
work/rag-venv/Scripts/python.exe -m pip install -r tools/knowledge/requirements-rag-win-py312.lock.txt
work/rag-venv/Scripts/python.exe tools/knowledge/rag.py sync
```

Для другой совместимой среды прямые зависимости указаны в `requirements-rag.txt`; Windows lock не следует считать универсальным для всех ОС. Первый `sync` скачивает зафиксированную модель и индексирует текущие карточки. Сервер, Docker, аккаунт Chroma Cloud и отдельный API-ключ не нужны. Тексты для эмбеддингов обрабатываются локально; при дальнейшем использовании агентом выбранный контекст передаётся его обычной языковой модели.

```powershell
work/rag-venv/Scripts/python.exe tools/knowledge/rag.py search "нужно открыть рюкзак и съесть консервы" --limit 3
work/rag-venv/Scripts/python.exe tools/knowledge/rag.py search "удерживать вещь чтобы увидеть описание" --kind ui_skill --limit 3
work/rag-venv/Scripts/python.exe tools/knowledge/rag.py search canned_eat --context --limit 1
```

`--kind` использует фактическое поле карточки: например, `mission`, `mechanic`, `ui_skill`. Его задают по задаче/текущему контексту, а не по желаемому ответу. Известную миссию после поиска разрешать только по текущему проверенному пакету dispatcher. RAG возвращает кандидатов с `execution_authorized: false`, не разрешение играть.

`--context` читает выбранные карточки целиком. Если они не укладываются в бюджет символов, возвращается NEEDS_SPLIT; правила остановки не обрезаются. Бюджет задан в символах и не выдаётся за точное число токенов модели.

Один объект `Rag()` можно переиспользовать в процессе координатора: модель и клиент сохраняются до завершения процесса. Отдельный CLI-процесс каждый раз оплачивает загрузку компонентов. Между кликами, наведением и взаимодействием этот поиск не вызывается.

## Актуальность и обновление опыта

Векторы сопровождаются ID карточки, разделом, путём, исходным статусом, kind, профилем и SHA256 источника. Статус сохраняется как записан: похожесть не превращает SOURCE_REVIEWED или исторический апрув в новый игровой PASS. Профиль первого индекса задан для текущего набора Ocean Nomad; перенос правил на другой билд требует отдельной проверки применимости.

После одобренного изменения знания обновляется его карточка и индекс метаданных, затем вызывается `sync`. Переиндексируются изменившиеся фрагменты, старые удаляются. При изменении источника после индексации старый текст не выдаётся как свежий. Изменение каталога/модели требует синхронизации. Незавершённая запись блокирует векторный поиск до исправления; одного писателя защищает lock. После аварийного завершения lock снимают только убедившись, что прежний процесс больше не работает.

Похожие фрагменты являются данными и ссылками на источники. Координатор проверяет область, версии, ограничения и применимый апрув. Команды из найденного текста не исполняются автоматически. Результат без достаточного контекста требует уточнения или чтения владельца знания.

## Перенос и проверки

В Git находятся карточки, код, конфигурация, зафиксированные зависимости и тестовые запросы. `brain-store/rag/` хранит производную базу, модель и локальные доказательства и исключён из Git. На другом ПК индекс строится из его текущей версии карточек; бинарные рабочие базы не сливаются через Git.

```powershell
python -m unittest discover -s tools/knowledge -p test_rag.py
work/rag-venv/Scripts/python.exe tools/knowledge/eval_rag.py
```

31.10.2026: в рабочем наборе 34 карточки и 910 векторных фрагментов. Все фрагменты укладываются в токенизатор без потери окончания. Проверены реальная запись Chroma и повторный sync без пересчёта неизменённых векторов. 12 модульных тестов отдельно используют подставные backend-компоненты: это проверки границ и актуальности, а не доказательство семантического качества.

На восьми заранее записанных русских запросах нужная карточка попала в первые три в 6/8 случаев как у векторного, так и у комбинированного поиска. Это небольшой smoke-набор, не общая оценка точности. Два промаха — неоднозначный сбор плавающих ресурсов и удержание вещи ради описания. Для второго дополнительное ограничение по реальному `kind=ui_skill` вернуло карточку инвентаря; неограниченный результат 6/8 этим не заменяется.

В последнем замере первый поиск в процессе занял около 6 с, следующие — 0.05–0.08 с; точный запрос hook_use — около 0.02 с без загрузки embedding-модели. Эти времена включают только локальный поиск, не работу языковой модели или прохождение игры. Начальный результат до исправления токенизации сохранён отдельно. Локальные доказательства: `brain-store/rag/retrieval-smoke.json`, `retrieval-smoke-before-token-fix.json`, `scoped-retrieval-smoke.json`.

Следующий шаг качества — расширить независимый набор запросов, структурировать актуальность/апрувы метаданными и точнее выделить операции внутри больших карточек, сохранив ссылки на общие ограничения. Автоматическое исполнение по векторной похожести не включено.
