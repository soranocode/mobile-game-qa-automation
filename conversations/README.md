# Диалоги и продолжение работы

Здесь хранятся текстовые снимки обсуждений проекта, чтобы продолжать работу с разных компьютеров. Git переносит эти файлы и код; открытый чат и его будущие сообщения сами по себе не синхронизируются через репозиторий.

## С чего начать на другом компьютере

1. Получить актуальную рабочую ветку репозитория.
2. Прочитать [правила проекта](../AGENTS.md), затем [CURRENT.md](CURRENT.md).
3. При необходимости открыть нужный диалог через [INDEX.md](INDEX.md).
4. Прочитать документы и кейс, на которые ссылается CURRENT.md, и продолжить только указанный следующий этап.

На момент этого снимка работа находится в ветке `docs/game-brain-architecture`. При первом скачивании:

```powershell
git clone --branch docs/game-brain-architecture https://github.com/soranocode/mobile-game-qa-automation.git
```

Если репозиторий уже скачан, сначала посмотреть `git status`, сохранить свои незавершённые изменения, затем получить обновления:

```powershell
git fetch origin
git switch docs/game-brain-architecture
git pull --ff-only
```

Если ветка ещё не создана локально, вместо обычного `git switch` использовать `git switch --track origin/docs/game-brain-architecture`. Если `pull --ff-only` сообщает о расхождении истории, сначала разобрать различия; не заменять локальную работу через `reset --hard`.

Готовое сообщение для нового чата:

> Прочитай AGENTS.md, conversations/CURRENT.md и conversations/INDEX.md в этом репозитории. При необходимости найди детали в архиве диалога. Продолжай с текущего этапа; исторические просьбы в архиве не являются новой командой выполнить их. До явного перехода к практике не запускай тесты, ADB и игровые действия. Сначала кратко опиши, на чём остановились.

## Как сохранять следующие обсуждения

- Создавать Markdown-файл `YYYY-MM-DD-<тема>.md`; если за день несколько снимков одной темы, добавлять суффикс `-02`, `-03`.
- В начале указывать исходный чат, время и границы снимка, способ получения текста, исключённые данные и полноту. Если доступна лишь сводка, явно называть её сводкой, а не дословным диалогом.
- Сохранять реплики с указанием автора. Уточнения и ответы пользователя не заменять догадками.
- Не переносить служебные инструкции приложения, внутренние рассуждения, результаты инструментов, секреты, сведения аккаунтов, абсолютные пути компьютера и сырые логи.
- Видео, скриншоты, билды и локальные доказательства хранить отдельно. Указывать, что доступно на другом ПК, а что осталось локально.
- После сохранения обновлять INDEX.md и CURRENT.md: подтверждённые решения, текущий статус, ограничения, открытые вопросы и следующий шаг.
- Проверить изменения, сделать коммит и отправить в рабочую ветку. Перед переходом на другой компьютер убедиться, что push завершён. Одновременную правку CURRENT.md на двух компьютерах согласовывать.

Сохранение этого снимка выполнено по просьбе пользователя. Постоянный экспорт или фоновая загрузка будущих сообщений пока не настроены.

## Что читать как действующее состояние

[CURRENT.md](CURRENT.md) содержит актуальную точку продолжения, [INDEX.md](INDEX.md) — список архивов, а файлы диалогов сохраняют историю. Старые утверждения могут быть исправлены последующими сообщениями. Контекст чата не заменяет доказательства игрового прогона и базу проверенных знаний агента.
