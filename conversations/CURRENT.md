## Текущий этап и ограничения

**Подготовка среды и одного сценария.** Пользователь просит двигаться строго поэтапно. Пока запрещены тесты, ADB, проверка подключения телефона, игровые действия и запуск кейса. Чтение старой просьбы «продолжай» или примера команды в архиве не снимает это ограничение. Последняя задача — сохранить диалог в GitHub для работы с нескольких компьютеров.

Репозиторий автоматизации: [soranocode/mobile-game-qa-automation](https://github.com/soranocode/mobile-game-qa-automation), приватный. Рабочая ветка — `docs/game-brain-architecture`; основная — `main`. Архитектура и архив публикуются в рабочей ветке. [Draft PR #1](https://github.com/soranocode/mobile-game-qa-automation/pull/1) ещё не означает слияния в main.

Первая игра — Raft Survival Ocean Nomad, Android; у пользователя есть телефон и базовый опыт запуска/правки Python. Ragdoll Sandbox — следующий возможный проект.

Долгосрочная цель — игровой агент с пространственным пониманием, поиском данных и накоплением опыта. Архитектура описана в [brain/README.md](../brain/README.md), [MEMORY.md](../brain/MEMORY.md) и [UNITY_BRIDGE.md](../brain/UNITY_BRIDGE.md). ## Согласованный первый блок

Игра: Ocean Nomad **2.11.0 (dev)**. Условия: первое открытие после установки по сообщению пользователя. Граница: открытие игры → первое главное меню. Настройки, «Играть», сюжетные диалоги и игровой мир относятся к следующим блокам.

Последовательность из предоставленного видео: начальная отрисовка → dev Setup с Remote Params и START → загрузка → приветствие Google Play поверх загрузки → окно Mail, если появляется → первое главное меню.

- Setup относится к dev-билду; параметры в рамках кейса не менять. START продолжает запуск.
- Google Play — наблюдение интерфейса, а не доказательство серверной авторизации. Отсутствие приветствия само по себе не FAIL.
- Пользователь подтвердил: Mail сейчас достаточно закрыть; выбранная кнопка несущественна. Неизвестно, ограничено ли окно dev-билдом; его отсутствие само по себе не FAIL.
- Около 28–29 секунд до меню в видео — временная метка для просмотра, не SLA или таймаут.
- Прохождение кейса не выполнялось. Неизвестные координаты, Setup-профиль, данные устройства и норматив ожидания нельзя выдумывать.

Unity-проект пока не скачан, не открыт и не запущен. MCP и внутриигровая телеметрия не подключены. Само наличие исходников не доказывает запуск Android-билда.

## Следующий шаг после сохранения диалога

1. Продолжить установку **Unity 6000.0.66f2** через [официальную страницу версии](https://unity.com/releases/editor/whats-new/6000.0.66f2). Для Android предусмотреть Android Build Support, SDK & NDK Tools и OpenJDK. Пользователю уже дана эта инструкция; завершение установки ещё не подтверждено.
2. Затем получить выбранную ветку GitLab в отдельную папку **вне репозитория автоматизации**. Настроить доступ Git, проверить LFS и зависимости, не переносить исходники игры в GitHub automation-репозитория.
3. Только после подготовки разбирать первое открытие проекта нужным Editor, стартовую сцену и дальнейшую Unity-интеграцию. Практические тесты и игровой запуск требуют явного перехода пользователя к этому этапу.

Перенос самого чата в отдельный проект интерфейса Codex ранее запрашивался, но не был завершён. Нельзя считать его выполненным по наличию папки или репозитория. Для продолжения с другого ПК сейчас используется сохранённый контекст в Git.
