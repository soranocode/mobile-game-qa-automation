# Game QA Demonstration Recorder 0.2.0

Отдельный UPM-пакет для записи действий и состояния **в Unity Editor 6000.0+**. Окно: **Window → QA → Demonstration Recorder**. Запись включается человеком в уже запущенном Play; сам пакет не начинает игру, не отправляет игровой ввод и не сбрасывает прогресс. В player сборки код не входит: окно/адаптер ограничены Editor; assembly компонентов имеет defineConstraints UNITY_EDITOR, исходники также защищены UNITY_EDITOR.

## Подключение

На другом ПК клонировать automation-репозиторий. Остановить Play и запись. В Unity Package Manager выбрать **Install package from disk** / **Add package from disk** и указать `package.json` из этой папки. Используется локальная зависимость на каталог пакета; зависимости Recorder5.1.7, Newtonsoft.Json3.2.1 и Unity UI2.0.0 объявлены в package.json.

Если уже установлена прежняя копия `Assets/QaDemonstrations`, сначала использовать мигратор из корня automation-репозитория:

```text
python tools/unity-demonstration/install_recorder.py --project PATH_TO_GAME
python tools/unity-demonstration/install_recorder.py --project PATH_TO_GAME --apply --migrate-legacy
```

Первая команда только показывает план. Вторая добавляет одну зависимость в manifest проекта и убирает только известные по SHA256 старые скрипты/.meta после создания резервной копии в `Library/GameQaDemonstrations/Migrations`. Неизвестные/изменённые скрипты останавливают миграцию; другие ассеты остаются на месте. Manifest игры и его резервная копия могут содержать приватные URL: они не печатаются целиком и не переносятся в automation Git. Ручной способ восстановления описан в документации установщика.

Старую и пакетную копии одновременно держать нельзя: они объявляют одинаковые классы. Для нового проекта без старой установки достаточно Package Manager или `--apply` без миграции.

Локальный путь работает, пока существует checkout пакета. На новом ПК или в другой копии игрового проекта его нужно подключить заново. Для воспроизводимого прогона фиксировать commit automation-репозитория вместе с версией пакета. Git URL с pin на commit/tag можно использовать после публикации пакета; наличие файлов локально не означает push. Собственный registry не требуется.

## Что уже есть

- Ввод клавиатуры/мыши, синхромаркеры, сцены, пропуски фокуса, запись Game View и LogicLight.
- JSON-журнал совместим с `ocean-demo/1`; новые session.json содержат ID/версию пакета и профиль адаптера.
- Адаптер Ocean Nomad читает существующие Movement/Camera/Joys через reflection. Приватные игровые классы и ассеты в пакет не включены. В меню состояние может быть неизвестно.
- Без подходящего адаптера записывается общий ввод/видео, а состояние игрока/камеры остаётся null. Нельзя приписывать другой игре управление Ocean Nomad.

Текущая запись ввода использует UnityEngine.Input (legacy Input Manager), как в проверенном Ocean Nomad. Проекты только с новым Input System потребуют отдельного адаптера ввода; совместимость с ними не заявлена.

Порядок записи, ограничения видео и синхронизации: [руководство](../../tools/unity-demonstration/README.md), формат и офлайн-анализатор находятся рядом с ним. Эти относительные ссылки доступны в полном automation checkout; при отдельном распространении пакета использовать документацию репозитория.

## Квесты и координаты Ocean Nomad

В0.2.0 запись автоматически включает модуль ocean.quest-world для профиля Ocean Nomad. Его quest_snapshot сохраняет источник/загрузку, отслеживаемые и активные миссии, шаги, UID целей, Value/Need/IsComplete. spatial_snapshot сохраняет соответствующие ObjectCollect-целям загруженные предметы: UID/instanceID/сохраняемый ID, активность/взятость/CanPickup, мировые/локальные координаты, расстояния до точки наведения и yaw/elevation относительно текущей камеры. Поддерживается сопоставление ObjectCollect с явно заданными uid; другие типы шагов имеют world_target_resolution_supported=false.

Исходный/финальный снимок, изменения до5Гц, heartbeat2с; список источников обновляется не чаще1Гц. До16активных квестов,32шагов/UID на шаг/целевых объектов; история наблюдавшихся ID ограничена64, скан Pickable4096, история завершений512. Флаги усечения показывают неполноту. Это выборки, не гарантированная запись каждого короткого перехода.

QuestManager читается из существующих TestGUI._activePanelList[*]._questManager, без Resolve/создания сервисов. При изменении этой структуры в другом билде или неоднозначном источнике данные unknown/unsupported, а не «квестов нет». Инвентарь и текущая выбранная цель Pickup пока не подключены. Старое членство в истории завершений не означает успех нового повтора.

Мировые координаты относятся к загруженным сценам, не к глобальной карте/не загруженному острову. Координаты относительно родителя игрока идут с его instanceID/преобразованием; родитель не объявляется автоматически плотом. Положительная yaw-поправка вправо, elevation вверх — это геометрия, не готовые значения Mouse X/Y. Точка наведения берётся из активного коллайдера или помеченного transform-fallback. Видимость, достижимость и безопасный маршрут остаются неизвестными. Пакет не поворачивает камеру и не ведёт персонажа.

Через MCP execute_code можно отдельно читать ограниченные снимки (это методы адаптера, не новые native MCP-tools):

~~~csharp
return QaDemonstrations.OceanNomadTelemetry.ReadSnapshot().ToString();
// Для соседних предметов заменить запрос выше на:
// return QaDemonstrations.OceanNomadTelemetry.ReadNearby(30f, 16).ToString();
~~~

Пустой Nearby при неизвестном игроке имеет query_status=player_unknown. Пустой список вообще не доказывает отсутствия предметов вне кэша/покрытия. Справочник и ограничения: projects/ocean-nomad/knowledge/observation/ON-OBS-QUEST-WORLD-001.md. Новая реальная запись модуля пока требует проверки; технические/синтетические проверки не являются прохождением квеста.

## Расширение

Общий код находится в Runtime/Editor, чтение конкретной игры — в Adapters. Core и MonoBehaviour sampler находятся в assembly GameQA.Demonstrations: defineConstraints UNITY_EDITOR исключает её из player compilation, сохраняя возможность добавить компоненты в Editor Play. Окно/видео находятся в GameQA.Demonstrations.Editor, адаптер — в GameQA.Demonstrations.OceanNomad.Editor; обе эти assembly ограничены платформой Editor. Все C# дополнительно защищены UNITY_EDITOR.

1. Для новой игры реализовать `IDemoObservationProvider` и зарегистрировать его через `DemoObservation.Register` при InitializeOnLoad. Провайдер должен читать существующее состояние, возвращать неизвестное при отсутствии данных и не создавать игровые сервисы. Выбирается один доступный провайдер перед записью; неоднозначность блокирует старт. Внешней asmdef нужна ссылка на GameQA.Demonstrations и ограничение Editor.
2. Для инвентаря, квестов или взаимодействий подписать небольшой модуль на `DemoCapture.SessionStarted`, `StateSampled` и `BeforeStop`. StateSampled вызывается после штатного снимка состояния, примерно10Гц; события игровых изменений можно слушать отдельно, если доступны. Подписки должны быть однократными и освобождаться по окончании сессии.
3. Записывать только необходимые изменения через `DemoCapture.RecordModuleEvent(moduleId, eventName, payload)` на главном потоке Unity. Общие seq/frame/t_ms назначает рекордер. Метод возвращает false вне записи; ID/имя ограничены80символами из букв/цифр/._-. Потоковые ошибки модуля записываются отдельно, не мешая остальным подписчикам и сохранению журнала. Признак complete означает полноту записи, не успех игры/модулей.
4. Для инвентаря понадобится начальный снимок, затем ID предмета, количество до/после и контекст изменения. Для проверки сбора связать это с целью/действием/квестом. Модуль инвентаря ещё не реализован; квесты/предметы уже сохраняет ocean.quest-world. Один ObjectCollect не подтверждает получение награды.

Событие расширения имеет kind=module и data `{module_id,event_name,payload}`; ошибки hook имеют kind=module_error и попадают в session.json.extension_errors. Старые события не переименованы. Анализатор пока интерпретирует управление Ocean Nomad; автоматический анализ новых payload добавляется вместе с конкретным модулем. Изменение контракта требует новой версии; несовместимое изменение журнала — новой schema. Не записывать аккаунты, токены, текст полей, весь инвентарь на каждом кадре или весь мир.

Основа формата пакета: [официальное руководство Unity](https://docs.unity.com/en-us/engine/6000.0/manual/packages-list/cus-pkg-development/custom-packages).
