# Доступ к Unity для игрового агента

Предложение для обсуждения с Unity-разработчиком. Доступ пока не получен. Перечисленные ниже имена — предлагаемые интерфейсы нашего проекта, а не список готовых команд Unity MCP.

## Что даст подключение

[Unity MCP](https://github.com/CoplayDev/unity-mcp) предоставляет мост к Unity Editor. Он поддерживает работу с объектами, сценами и тестами; пользовательские возможности проекта можно открыть через [custom tools](https://coplaydev.github.io/unity-mcp/reference/tools/core/execute_custom_tool).

Для игрового агента полезнее небольшой согласованный набор операций чтения, чем произвольное изменение объектов. Инвентарь, условия завершения миссий и игровые идентификаторы могут быть реализованы собственным кодом игры, поэтому их нужно отдельно подключить к интерфейсу.

## Минимальный набор данных для первого пилота

1. **`get_runtime_context()`** — версия билда/кода, режим Editor/Android, сцена, идентификатор игровой сессии, экземпляр мира и признак загрузки/паузы.
2. **`get_player_state()`** — положение и направление игрока, положение/ориентация камеры, система координат и время снимка. Для плота — идентификатор и его преобразование.
3. **`get_nearby_objects()`** — ограниченный по радиусу/количеству список объектов: идентификатор, тип, положение, активность, доступность для взаимодействия и происхождение каждого признака. Близость не равна видимости или достижимости.
4. **`get_task_state()`** — текущая миссия, её идентификатор, видимые условия/счётчики, состояние прогресса. Эти данные отражают реализацию и сами по себе не доказывают правильность требований.
5. **`get_inventory()`** — идентификаторы предметов и количество, если это нужно выбранной миссии.
6. **`capture_view()`** — изображение игрового вида, связанное с временной меткой или frame ID снимка состояния.
7. **`perform_input()`** — ограниченный обычный игровой ввод с идентификатором действия, длительностью и результатом отправки. Нужен отдельный исполнитель для Editor и Android.

Первую интеграцию можно сократить до контекста, положения/камеры, состояния одной миссии и изображения. Доступ к остальным данным добавлять по необходимости.

## Контракт наблюдения

- Источник каждого поля должен быть известен: игровое API, Editor inspection, Android или вывод компьютерного зрения.
- Общий snapshot/frame ID предпочтителен. Если данные получены в разные моменты, сохранять отдельные времена и отмечать несовпадение.
- Отсутствующее поле возвращать как неизвестное/неподдерживаемое, а не как ноль, пустой инвентарь или отсутствие объектов.
- Фильтровать объём выдачи. Не отправлять модели полную иерархию сцены на каждом шаге.
- Статический тип объекта и его идентификатор отделять от текущего положения. Не обещать постоянство runtime instance ID между сессиями.
- Координаты возвращать с системой отсчёта, единицами и версией карты. Преобразования плота, игрока и камеры должны быть согласованы.

## Разделение режимов QA

**Изучение Editor:** можно инспектировать сцену и понимать связи объектов. Полный доступ к сцене даёт больше информации, чем видит игрок; это отмечается в каждом результате.

**Проверка игрового поведения:** действовать обычным игровым вводом и проверять результат. Телепортация, выдача предмета или принудительное завершение миссии меняют проверку. Такие операции не считаются её прохождением.

**Подготовка исходного состояния:** разработчик может отдельно предоставить загрузку тестового слота или иной воспроизводимый старт. Он должен быть явно отделён от действий проверяемого сценария. Сброс прогресса не входит в текущую авторизацию.

**Мобильный билд:** Editor MCP не является каналом к установленному APK. Для чтения внутренних данных Android потребуются отдельная QA-телеметрия в тестовом билде или иной поддерживаемый разработчиком механизм. Без него доступны возможности Android-моста. Результаты разных сред не объединяются как равнозначные.

## Что выяснить у разработчика

- Версия Unity и возможность подключить сторонний пакет в отдельной ветке.
- Можно ли получать перечисленные поля без изменения проверяемой игровой логики.
- Как идентифицировать один и тот же билд, слот и мир между источниками.
- Как воспроизводить начало выбранной миссии.
- Какие операции являются только чтением, какие — обычным вводом, какие меняют состояние для подготовки.
- Есть ли возможность включать интерфейсы только в тестовом окружении/билде.

MCP и Unity пока не устанавливаем и не подключаем. Сначала нужен подтверждённый доступ и согласованный объём интеграции.
