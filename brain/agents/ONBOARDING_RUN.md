# Инструкция координатору: изученный онборд одним прогоном

28.10.2026. Ocean Nomad 2.11.0 dev, Unity Editor. Этот файл готовит запуск; сам по себе не разрешает играть. Запрос на запуск должен прийти от человека. Миссии задают цели, навыки выполняют переиспользуемые действия. Все перечисленные миссии относятся к онборду, независимо от файла исполнителя.

## Порядок

Порядок хранится в [onboarding-sequence.json](onboarding-sequence.json):

1. `intro` — пройти сюжетные страницы: «Далее», на последней обязательно «Завершить»; дождаться свежего Done.
2. `control` — выполнить реальное движение и поворот камеры, завершить оба шага.
3. `wooden_hook` — изготовить деревянный крюк обычной кнопкой Create, закрыть Craft, получить свежий Done.
4. `hook_use` — обычным крюком выловить три квестовых объекта; учитывать фактически пойманные цели и завершить 3/3.
5. `shark_attack` — запустить миссию, закрыть читы/диалог, подойти по настилу на дистанцию ближнего боя, навестись и отогнать акулу крюком. Нужны свежие исход боя и Done миссии.

Это текущий подготовленный набор, а не перечень всех квестов релиза. `hands_collect` остаётся отложенной: проблема активации в Editor, отдельного подготовленного handler в каталоге нет. Не вставлять её в запуск и не засчитывать как пройденную.

## Подготовка до старта прогона

Назначить одного исполнителя Unity MCP. Специалисты памяти не отправляют ввод; новые агенты на каждый клик или известную миссию не нужны. Проверить комплект командой `python tools/portable/bootstrap.py check`. Она строит восемь коротких пакетов без Unity. При REVIEW_REQUIRED пересмотреть изменённые источники; не обновлять хеши вслепую.

Один раз восстановить runtime по [RESTORE_ON_NEW_PC](../../docs/RESTORE_ON_NEW_PC.md). `repoRoot` ниже — абсолютный путь текущего репозитория. Импорт ничего не запускает; openRuntime подключается к ожидаемому проекту и проверяет свободного владельца, но не включает Play или новую игру.

```js
var {pathToFileURL} = await import('node:url');
var portable = await import(pathToFileURL(repoRoot + '/tools/portable/runtime.mjs').href);
var qa = await portable.openRuntime();
```

В текущей запущенной и неприостановленной сцене Game прогреть по одной, отдельными вызовами инструмента с достаточным timeout:

```js
await qa.prepareMissions(['intro']);
await qa.prepareMissions(['control']);
await qa.prepareMissions(['wooden_hook']);
await qa.prepareMissions(['hook_use']);
await qa.prepareMissions(['shark_attack']);
```

Runtime сверяет источники, текущую эпоху/сцену, готовит существующие handlers и пять команд управления циклом без игровых кликов. Все выбранные команды Unity готовятся до начала замера. На повторе тех же epoch/revision используется прогретый пул. При смене сцены, reload, исходников или неопределённости соединения прежний план недействителен.

Не перечитывать README, CURRENT, полный справочник и историю между миссиями. Стабильный вход после сжатия контекста — `portable.getRuntime()`. Если процесса уже нет, восстановить runtime и прогреть заново. После изменения исходников нужен новый idle Node процесс: новые хеши не обновляют старые ES-модули и closures автоматически.

## Запуск конвейера

По актуальному запросу человека — один вызов:

```js
var result = await qa.runPipeline({
  missions: ['intro','control','wooden_hook','hook_use','shark_attack'],
  taskId: 'human-onboarding-' + Date.now(),
  authorized: true,
  lookahead: 2
});
nodeRepl.write(result);
```

`authorized: true` выставляется только для текущего применимого запроса человека. `runMissions` — alias этого конвейера. Во время текущей миссии готовятся следующие два пакета без MCP; после свежего завершения и cleanup следующая готовая миссия запускается без модельного хода. На границе проверяются текущий контекст и неизменность источников. Один владелец ввода и baseline ошибок сохраняются до конца цикла. Телеметрия пишется в процессе, анализ и предложения знаний финализируются после цикла. Активные знания не меняются. Описание и пределы реализации — [PIPELINE.md](PIPELINE.md).

Запрос на всю цепочку может длиться дольше 60 с. Задать `timeout_ms` с запасом к сумме текущих бюджетов миссий; не переносить короткий timeout трёх быстрых миссий. При использовании `functions.exec` держать вызов Node REPL ожидаемым через `await`, позволить внешней ячейке вернуть running cell ID и забирать результат через `functions.wait` короткими ожиданиями. Не запускать вторую копию цепочки при отсутствии немедленного ответа. Таймаут/сброс процесса не означает, что последний Unity-ввод не произошёл: сначала отмена и свежее состояние, без слепого повтора.

## Поведение во время выполнения

- Начальная точка — уже открытый игровой мир. Вход с холодного запуска и «Начать игру заново» добавлять только по отдельному запросу. Подготовка не должна запускать Play или удалять прогресс.
- Каждую нужную миссию включать через Quests только если она ещё не активна; существующую активную не перезапускать. После выбора закрыть чит-панель через Назад, затем известный диалог. Между действиями внутри чит-панели сохранить изученную паузу 1 с.
- В `intro` при замене Next на Finish и доказанно неотправленном клике сразу выбрать актуальную Finish. Не заканчивать на последних словах или исчезновении Next. Не переходить к control без свежего завершения.
- Знакомые действия выполняет подготовленный handler. Не вставлять рассуждения, скриншоты всей сцены, исследование исходников или сообщения после каждого клика. Неизвестное состояние вернуть координатору; известную краткую задержку обработать ограниченным ожиданием/повтором по существующему контракту.
- Отправленный Create не повторять вслепую. Наличие старого предмета и факт sent не заменяют свежего итога миссии. Не включать бесплатный крафт или выдавать предметы кодом.
- `hook_use` использует существующие очередь целей, наведение и цикл крюка. Динамические координаты и фактические сборы получать заново; отдельное решение модели между наведением и броском не нужно.
- `shark_attack` использует изученные движение, наведение и ближний бой. При необходимости handler переключает уже доступный Hook со вторичного действия. Если крюка нет, это невыполненное предусловие. Самостоятельный дополнительный вызов атаки, новая игра и обход отсутствия события в эту цепочку не включены.
- Стоп человека, неожиданная красная ошибка, неизвестный исход ввода, потеря контекста или исчерпание бюджета останавливают текущий handler и оставшиеся миссии. Для отмены использовать `qa.stop()`/AbortSignal конвейера, дождаться cleanup владельца. Не стартовать новый handler, пока старый не завершился.

## Итог после прогона

Координатор получает кратко: результат каждой миссии, время, причину остановки при наличии и путь evidence. Локально сохраняются events.ndjson, report.json, analysis.json и knowledge-candidates.json. При cleanup_confirmed: false после восстановления связи выполнить qa.recoverStoppedCycle(); это только подтверждение остановки, без повтора миссий. Полные журналы сохраняются локально. Время подготовки отделять от выполнения. `PASS_SEQUENCE` — только когда все пять вернули подтверждённый успех в этом запуске. Отложенную hands_collect не включать в число пройденных.

Статус на 27.10: control/wooden_hook новой обвязкой прошли и одобрены по скорости (7.393/7.612 с вместе с выбором в читах). intro потребовал подсказки Finish; исправление подготовлено и проверено офлайн, автономный повтор ещё нужен. Навыки hook_use и борьбы с акулой изучены ранее, но полная цепочка пяти новых handlers одним прогоном ещё не проверена. Не обещать её время по сумме старых несопоставимых измерений.

## Сообщение, которое можно передать координатору

> Прочитай brain/agents/ONBOARDING_RUN.md и PIPELINE.md. Используй portable runtime: подготовь по одной intro → control → wooden_hook → hook_use → shark_attack; затем по моему запросу запусти qa.runPipeline одной очередью. Во время текущей миссии готовь следующие два пакета без MCP; все Unity команды прогрей до старта. Один исполнитель и наблюдатель ошибок на весь цикл, свежий итог каждой миссии, без обсуждения промежуточных кликов. В intro обязательна «Завершить». Новую игру и hands_collect автоматически не добавляй. При стопе/неизвестном исходе/неожиданной ошибке прекрати очередь. Анализ и предложения знаний — после всего цикла, без правок активной памяти. Эта инструкция готовит запуск; текущий прогон я запрошу отдельно.
