# Изолированные роли и готовые пакеты

Это рабочая организация внешней памяти, не обучение весов модели. Родительский чат не обязан хранить справочники специалистов.

## Обычный вызов

Координатор выбирает одну текущую подзадачу. `tools/knowledge/dispatch.py` находит её по явному UID/алиасу, проверяет ревизии источников и возвращает короткий пакет. Неизвестные/неоднозначные задачи не получают случайного профиля. Составной запрос разбивается на очередь, следующий пакет загружается перед следующей миссией.

Для знакомого пакета не нужен новый ход агента специалиста: назначенный исполнитель использует готовый entry point. Специалист нужен для подготовки нового знания, проверки пакета или конкретного пробела. Он не выдаёт команды Unity по каждому клику.

Пример из корня репозитория:

```powershell
python tools/knowledge/dispatch.py hook_use --prepare
python tools/knowledge/dispatch.py hook_use --packet
```

Первая команда готовит только текстовую память на диске. Она не подключается к MCP, не прогревает C# и не запускает игру. Повтор возвращает тот же пакет при неизменных источниках.

## Передача специалисту

Запускать свежий контекст без истории родителя: в доступном инструменте collaboration это `fork_turns="none"`. Не использовать старых агентов, уже получивших весь длинный диалог. Передать только текущую цель, выбранный пакет, применимые ограничения человека и конкретный вопрос. Не копировать CURRENT, полную историю, каталог навыков или иерархию Unity.

Специалист не редактирует файлы, не играет и не вызывает других агентов. Ответ до 1600 символов: задача, entry point, применимость, предусловия, критерии результата/остановки, ID источников и пробелы. Если объёма недостаточно, вернуть `needs_context` с точными ID. Нельзя обрезать важное ограничение ради лимита. Следующий специалист не получает весь ответ предыдущего: ему передаются только необходимые смысловые результаты.

Для JSON ответа планировщика есть проверка `python tools/knowledge/dispatch.py hook_use --check-reply LOCAL_REPLY.json`: слишком длинный ответ не передаётся дальше, выдуманный entry point отвергается. Проверка формы не заменяет смысловую проверку и не даёт разрешение играть. Сам первый ответ агента всё равно уже расходует контекст родителя; лимит промпта не гарантирует его соблюдение.

Технические разрешения наследуются от родителя. Инструкции «только чтение» и выключенные отдельные возможности профиля не создают отдельную песочницу и не гарантируют физическую недоступность всех MCP. Единственный владелец игрового ввода назначается координатором.

## Спящий режим

Есть два разных кеша:

- **Долговременный пакет:** UID задачи, короткий план, ограничения, entry point, проверенные хеши карточек и кода. Лежит в `brain-store/memory-packets`, вне Git. Исходные карточки остаются в своих темах; пакет не копирует их исторические разделы.
- **Прогретые команды:** объекты/скомпилированные команды в процессе исполнителя и Unity. `tools/agent-runtime/mission-pool.mjs` хранит подготовленные handlers по миссии, эпохе Unity и ревизии пакета. Сам пул не подключается к MCP. Для реального исполнения существующий игровой адаптер должен передать ему run/cancel.

Завершённый агент не должен крутиться в цикле ожидания. Его полезный результат сохраняется; готовые команды могут ждать следующего явного задания без обращений к модели. После закрытия процесса, перезапуска Unity или domain reload прогрев утрачивается. Повтор не должен молча компилировать весь набор во время исполнения: сначала отдельная подготовка.

Для hook_use добавлен `tools/agent-runtime/hook-runner.mjs#prepareHookMission`: он восстанавливает существующие bindings/AimHookAction, прогревает команды отдельно от запуска и возвращает run/cancel для пула. Во время run используются свежие подписки и прежний `runHookTrial`, не новый способ прохождения. В `onboarding-runner.mjs` теперь также есть отдельные factories intro/control/wooden_hook/shark_attack. Общее описание — `tools/agent-runtime/PREPARED_MISSIONS.md`. 27.10 control/wooden_hook нового слоя прошли live и одобрены по скорости; intro исправлен после подсказки Finish, полный расширенный набор ещё требует одного общего прогона.

Пример интерфейса исполнителя (не самостоятельный запуск и не источник разрешения):

```javascript
await pool.prepare({mission:'hook_use', epoch:currentUnityEpoch, revision:packetRevision,
  factory:()=>prepareHookMission({session,parameterDirectory})});
// Только после актуального задания и проверки свежего игрового контекста:
await pool.run({mission:'hook_use', epoch:currentUnityEpoch, revision:packetRevision,
  taskId:currentHumanTaskId, authorized:true, input:currentTaskInput});
```

## Что не кешируется

Не сохранять в статическом пакете разрешение действовать, исключения Console, текущие координаты, runtime instance ID, удержание ввода, текущую миссию или результат прошлого запуска. Совместимость проекта/билда/профилей, актуальная сцена и мир проверяются по свежему контексту. Геометрия/угроза/снаряжение/шаг изменились - активный план обновляется или останавливается, даже если хеши карточек прежние.

После изменения карточки или исходника dispatcher возвращает REVIEW_REQUIRED без старого плана. Это защита от устаревшей ручной выжимки. Координатор читает только изменённые владельцы знаний, проверяет выжимку и обновляет её хеши. Не регенерировать хеши вслепую. Критичное новое ограничение останавливает текущий навык сразу; куратор не откладывает его до конца прогона.

## Работа после задачи

Исполнитель возвращает компактный итог и сохраняет детальную телеметрию локально. Куратор вызывается при новом факте/ошибке/апруве и предлагает обновление владельца знания с датой, билдом, источником, доступностью доказательств и различением человеческой оценки и агентного наблюдения. Повторный успех не порождает копию карточки.

## Роли и перенос

В `.codex/agents/` подготовлены ocean-ui, ocean-quests, ocean-navigation, ocean-combat, ocean-memory-curator и ocean-mcp-executor. Обычно нужен один специалист, а для знакомого кешированного выполнения - ни одного дополнительного специалиста. Только назначенный executor отправляет игровой ввод. В Cursor есть переносимый read-only профиль `.cursor/agents/ocean-memory.md` с тем же протоколом.

Проектные определения Codex находятся в корне репозитория автоматизации. Для их штатного обнаружения открывать этот репозиторий как рабочий проект; наличие вложенной папки не доказывает, что текущий старый чат уже перечитал конфигурацию. В текущем чате изоляция дополнительно задаётся явным запуском без истории. Глобальные настройки, модель, права и MCP не меняются.

Новый чат координатора возможен после передачи текущей цели и ссылки на dispatcher; отдельный пользовательский чат на каждого специалиста не нужен. Старая история этого чата не удаляется созданием файлов. Автоматическая пересылка переписок между Codex и Cursor не требуется: общими являются файлы и пакеты.

## Проверка эффекта

Измерять размер переданного пакета, число реально вызванных агентов, время выборки, cache hit, подготовку и исполнение отдельно. Суммировать расходы всех агентов. Число байтов подготовленного текста не равно точным токенам всего запроса. Субагенты могут увеличить суммарный расход; экономия требует сравнения на одинаковых задачах.

Официальный формат проектных TOML агентов и наследование разрешений: [OpenAI Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents). Cursor профиль следует локальному навыку create-subagent. Нативное обнаружение профилей в новой среде требует проверки; отдельные handlers пула уже прошли live, полный расширенный набор ещё не подтверждён; офлайн проверены синтаксис, маршрутизация, бюджеты, кеш, подготовка hook_use и отмена ввода. Изолированный субагент получил план hook_use из одного пакета без истории; первое превышение лимита ответа потребовало сокращения, поэтому лимиты ответа ещё нужно проверять на границе передачи, а не считать гарантированными одним промптом.
