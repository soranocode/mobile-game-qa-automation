# Короткий старт координатора

Проект: Ocean Nomad, Unity Editor. Текущий этап — оптимизация памяти и повторных вызовов, не новый игровой прогон.

Координатор и исполнитель — два отдельных агента. Ты в этом чате координатор: не вызывай Unity MCP, не подключайся даже для наблюдения и не запускай runtime. Создай/используй одного отдельного `ocean-mcp-executor` и передай ему весь текущий разрешённый цикл. Он единственный владелец Unity; ты параллельно готовишь пакеты без MCP. Точный протокол, способ передачи профиля и короткая команда для чата — [ROLE_HANDOFF.md](ROLE_HANDOFF.md). Отсутствие делегирования — блокер, не повод совмещать роли.

Изученный онборд одним прогоном: [ONBOARDING_RUN.md](ONBOARDING_RUN.md). Порядок из [onboarding-sequence.json](onboarding-sequence.json): intro → control → wooden_hook → hook_use → canned_eat → shark_attack. hands_collect отложена; новая игра не входит автоматически. [PIPELINE.md](PIPELINE.md) описывает подготовку двух следующих пакетов параллельно текущей миссии и анализ после всего цикла. Новая обвязка проверена офлайн, игровой замер ещё нужен.

- Начни с AGENTS.md и `python tools/knowledge/dispatch.py --list`. Не загружай всю переписку, CURRENT и справочник.
- Для одной знакомой задачи: `python tools/knowledge/dispatch.py hook_use --prepare`. Для чтения краткого пакета добавь `--packet`. Есть также intro, control, wooden_hook, shark_attack, settings, raft_navigation, shark_defense.
- Уже подготовленный пакет не требует нового специалиста. При пробеле назначь одного профильного агента без истории родителя, передай только цель и пакет. Ответ до 1600 символов, с проверкой перед передачей дальше.
- Только один назначенный исполнитель отправляет ввод Unity. Подготовка команд отдельно от запуска; повтор использует тот же подготовленный набор при совпадении эпохи Unity и ревизии.
- Компоненты: `tools/agent-runtime/mission-pool.mjs`, `hook-runner.mjs`, `onboarding-runner.mjs`. Все изучаемые миссии — онборд, включая hook_use. Миссия задаёт цель и выбирает переиспользуемые навыки; не смешивать эти сущности из-за имён файлов. control/wooden_hook новой обвязкой прошли и одобрены 27.10; intro исправлен после подсказки Finish, автономный повтор ещё нужен. Подробности — `tools/agent-runtime/PREPARED_MISSIONS.md`.
- Исполнитель использует `getMissionPool()` и проверяет `readiness` всех выбранных миссий; координатор не ищет и не перехватывает его REPL-переменные. Текстовый кеш не означает готовность Unity.
- В отдельном агенте-исполнителе: `tools/portable/runtime.mjs#openRuntime/getRuntime`, затем `qa.prepareMissions([UID])` по одной и `qa.runPipeline(...)`. Эти вызовы координатору запрещены. Регистрация создаёт локальные обработчики; Unity выполняет и компилирует команды при первом фактическом использовании. Во время миссии параллельно готовятся только пакеты следующих задач. Повтор не собирает команды из документации. `qa.runMissions` — alias конвейера.
- Текущие координаты/сцена/активность игры неизвестны до свежего наблюдения. Наличие сохранённого пакета или старого запроса не разрешает запускать игру.
- REVIEW_REQUIRED означает проверить изменённые источники и выжимку; не обновлять хеши механически.
- Подробный протокол читать для изменения этой архитектуры: `brain/agents/PROTOCOL.md`.

Для штатного обнаружения `.codex/agents/` открыть именно корень репозитория автоматизации как проект. Новые пользовательские чаты для каждого специалиста не нужны. Эта точка продолжения не переносит локальные сырые доказательства и рабочие процессы Unity на другой ПК.
