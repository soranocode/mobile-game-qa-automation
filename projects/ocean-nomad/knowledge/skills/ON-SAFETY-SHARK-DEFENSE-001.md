# ON-SAFETY-SHARK-DEFENSE-001 — спящая реакция на нападение

Ocean Nomad 2.11.0 dev, Unity 6000.0.66f2, 26.10.2026. Реальные signal→бой→retreat прогоны подтверждены: огнестрел и Hook. Человек одобрил каждый отдельно. Для восстановления произвольных задач есть PriorityTask API и 4 unit checks; полный live сценарий «прервать меню-тест → бой → продолжить тот же тест» пока не проверен.

## Триггер и ожидание

Установить prepareDefense(session), затем setArmed(true). Семь AppDomain delegates компилируются ДО боя. Idle: подписка на существующий SharkAttacked, D.OnNewLog маркер Showing alert 'SharkAttack', проверка живого IsSharkAttack. Раз в секунду проверяется/обновляется привязка живой акулы; координаты цели и карта в ожидании не запрашиваются. Для запуска не важны квест/чит/таймер. Модель и Console-поллинг не участвуют в частом цикле. Callback живёт в Unity независимо от сброса Node/MCP клиента, но до Play stop/domain reload; это не автоматически установленный пакет или автозапуск после перезапуска Editor.

## Реакция

cancelMain → freeze checkpoint → Close/Back → свежая геометрия/оружие/акула → staging к атакуемой foundation, если акула ещё подходит → точка на поддержанном настиле для реального range → обычные Move/Look/UIUse → damage + retreat. Код tools/shark-defense/reactor.cs.txt вызывает тот же бой для квеста и обычной атаки. Карта — native plan.cs.txt, подготовленные UI helpers переиспользуют проверенные мотор/наведение. Координаты не являются памятью маршрута.

Range — из реально экипированной модели; в Hook эпизоде 1.1 и melee camera spherecast .33. Для огнестрела отдельный одобренный контракт ON-COMBAT-FIREARM-SHOT-001. С 27.10 Rifle использует отдельную проверку HitScanShooter.CollectHits и IsRayBlockedBySolid, а не melee gate. Смена/перезарядка всех пушек не освоены.

## Результат и приоритет

Retreat засчитывается только при свежем событии enemy.shark.AttackRaft.retreat, завершившейся атаке и фактическом HP damage. Death отдельно eliminated. Timeout/исчезновение флага без причины/unknown UI/ошибка/нет опоры/нет прогресса/45с budget => needs_review, ввода нет, задача не продолжается. Красная ошибка по указанию человека остаётся стоп-условием.

PriorityTask сохраняет вид test|training и ограниченный JSON checkpoint со смысловым шагом. После подтверждённой защиты resume(callback) получает этот шаг и обязан заново проверить UI/мир, затем явно выбрать retry_after_revalidation или step_already_completed. Координатный/деструктивный клик автоматически не повторяется. Старые задачи вне этой оболочки сами не продолжаются. Обычные UI/route/aim/motor wrappers получили preempted_shark guards; источник боя использует отдельные state keys.

## Доказательства и причины прежнего простоя

Первый Hook прогон: wake зарегистрирован, план отказал start_outside_supported_region. Spawn был рядом с LotteryBox в зоне дополнительного obstacle/water reserve, хотя CharacterController grounded. Теперь план отдельно различает not_grounded_yet и безопасное краткое восстановление физически поддержанного тела, включая локоть вокруг препятствия. Recovery ограничено .45 unit/.05–.16с/6 попытками; это кандидат с проверенным read-only планом, не отдельный общий апрув выхода из любого застревания.

Следующий запуск блокировался двумя красными ошибками повторного старта уже активного shark_attack. Не повторять старт активного квеста. Отдельные 5 красных PlayerLoop recursive errors возникли при MCP composited screenshot, позже остановки первого подхода; этот способ захвата исключён. Ошибки не скрывались: разобраны, новый тест начат с новой baseline после устранения вызывающего действия.

Финальный Hook live: первый подход начат через ~25мс после wake; первый урон через 2.743с, 6 damage events 4+4+5+4+4+6=27, HP100→73, retreat через 9.323с, ошибок0, grounded=true, input отпущен. Человек: «да отлично». Огнестрел ранее: damage44, retreat2.923с; отдельное одобрение. Во всех этих успешных боях активный checkpoint отсутствовал — живое автоматическое возобновление ещё не доказано.

prepare/arm/read/stop: tools/shark-defense/install.mjs. Явный stopDefense снимает подписки/ввод. Новая попытка после needs_review — только после разбора причины; не сбрасывать защиту ошибок молча. Raw evidence локально outputs/unity-mcp/shark-defense/2026-10-26T08-27-00-043Z/. После обучения Hook 26.10 использовался armed, melee_only; текущий выбор режима см. ниже. Пакет/автоподключение между ПК пока не сделаны.

## Экипированное ближнее или дальнобойное оружие — 27.10.2026

Прямое требование человека: включить дальнобойное оружие в пассивную защиту. Обычное дежурство теперь использует SessionState QaAgent.SharkDefense.require_melee=false; true оставлять только для явно выбранного обучения Hook/ближнему бою. Используется фактически экипированное оружие и его модель, без принудительной смены, выдачи патронов, ремонта или изменения урона. Проверенные типы: Hook и огнестрел по ON-COMBAT-FIREARM-SHOT-001 (эпизод Rifle с activity Pistol); прочие пушки и перезарядка отдельного live апрува не получали.

Перед включением разобран needs_review/expected_melee_weapon: в руках Rifle, CurrentActivity=Pistol, Hook во втором действии; новых красных ошибок 0. Причина была в оставшемся режиме melee_only. По новому запросу снято именно это ограничение, подготовлены прежние семь jobs и восстановлены подписки. Подготовка 2.683 с; armed=true, source_bound=true, status=sleeping, новых красных ошибок 0. Это проверка включения режима, не новый подтверждённый огневой бой. Текущий режим живёт в текущем Play/domain; локальная активация brain-store/agent-runtime/shark_defense/evidence/ranged-*.json и passive-latest.json.

Для выборочного пакета достаточно контрактов защиты, Hook и огнестрела, навигации, управления и ошибок. Общая ON-MECH-MELEE-001 остаётся в справочнике для конкретного пробела, без загрузки седьмой карточки на каждую активацию.

## Стрельба с места и прежний ближний бой — 27.10.2026

Прямое уточнение человека: при срабатывании определить ближнее/дальнобойное оружие; с дальнобойным оставаться на месте, навестись и стрелять, перемещаться только при препятствии на линии огня; ближний подход оставить прежним. Перед изменением текущий обработчик оказался в needs_review/approach_outside_planned_region: в журнале Rifle/ranged и два ненужных подхода. Красных ошибок 0; причина разобрана, обработчик остановлен перед заменой.

Теперь ranged начинает с обычного Look без карты/маршрута. После наведения Rifle-проба использует тот же публичный read-only HitScanShooter.CollectHits, что игровой RifleShooter: центральный луч, sphere .25, сортировка попаданий. Подтверждённая цель разрешает обычный UI use; вне дальности — ограниченное ожидание на месте. Другая цель, полный буфер или неизвестный источник останавливают, а не запускают подход. Только подтверждённый solid между камерой и целью через IsRayBlockedBySolid разрешает до трёх безопасных перестроений позиции. Планировщик выбирает близкую доступную точку с проверенной линией выстрела; после движения выполняется новое наведение и новая проверка. Ближний .33 gate и прежний подход/стадирование сохранены.

В read и событиях добавлены weapon_uid, weapon_family, ranged_repositions, ranged_stationary, ranged_sight и ranged_reposition. Двенадцать безвводных проверок точной функции выбора действий прошли; старый melee hit gate совпал с сохранённым исходником. Все семь jobs и новый reactor скомпилированы в реальной Unity, новых ошибок 0. Это проверка ветвления/компиляции, не новый live апрув стрельбы с места или обхода укрытия. Текущий код установлен и включён в пассивное ожидание; старые успешные огневые эпизоды относятся к прежней версии. Локальные доказательства: brain-store/agent-runtime/shark_defense/stationary-ranged-2026-10-27/.
