# ON-QUEST-INTRO-001

Ocean Nomad 2.11.0 dev, Unity Editor. Обновлено 27.10.2026. Последний прогон потребовал подсказки человека на финальной кнопке; исправление подготовленной обвязки проверено офлайн, повторный автономный прогон после исправления ещё не выполнялся.

Цель: закончить сюжетные страницы и получить свежий Done экземпляра intro. Появление Next/Finish, отправленный клик и исчезновение окна сами по себе не доказывают завершение.

Рабочий маршрут: TestGUI → Quests → intro, если он ещё не активен; затем закрыть панель Назад. По показанной странице нажимать Next, на последней Finish. Использовать обычный selected-control.cs.txt: левая область уже учтена, дополнительное смещение может вывести клик за кнопку. Известное перекрытие обрабатывается коротким ограниченным повтором без поиска всей документации. Не запускать следующий квест до свежего завершения intro.

Последний шаг обязателен: «Завершить» / Finish нажимается там же в нижней области интерфейса, по актуальной кнопке. Если между чтением страницы и кликом Next исчезла, исполнитель получает подтверждённое отсутствие отправленного ввода (ноль найденных целей либо not_sent_target_changed), сразу читает текущую кнопку и переключается на Finish. Это не повод повторять запуск миссии или исследовать сцену. Неизвестный исход или несколько совпавших целей по-прежнему останавливают ввод. После Finish дождаться свежего Done с учётом fade; не дублировать уже отправленный Finish только из-за задержки события.

27.10: человек указал «ты на экране завершить просто нажми туда же на кнопку завершить». Finish отправлен обычным selected-control, окно закрылось. Наблюдатель был снят слишком рано (через 160 мс), поэтому свежий Done этой исправленной вручную попытки не сохранён; это assisted run, не автономный PASS. Причина остановки новой обвязки — not_sent на смене цели после Next. Регрессионные проверки теперь покрывают замену Next на Finish и задержанный Done. Требование человека добавить последний шаг принято.

Подготовка: `tools/agent-runtime/onboarding-runner.mjs#prepareIntroMission`. Пул хранит готовый handler до смены эпохи Unity/ревизии. Подготовка компилирует точные команды без игровых кликов; run использует свежую подписку, обычный UI и компактный результат. Повтор не восстанавливает план из переписки.

Источники: объяснения человека; StoryboardWindowView.cs (Next/Finish, текст страницы); прежний локальный отчёт `outputs/unity-mcp/quest-regression/2026-10-26T11-38-16-608Z/intro-verified.json` со свежим intro 1/1. Новый слой prepare/run не получает автоматически статус этого старого прогона. Неизвестные окна, новые ошибки, потеря источника, неизвестный исход ввода и стоп человека завершают попытку.
