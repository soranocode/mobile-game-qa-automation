# ON-UI-INVENTORY-001 — инвентарь и операции с предметами

Дата: 29.10.2026. Ocean Nomad 2.11.0 dev, Unity Editor; совместимость другой сборки проверяется отдельно.
Статус: SOURCE_REVIEWED + PARTIAL_AGENT_VERIFIED, обучение в процессе. Апрува нового навыка и подтверждения полного покрытия пока нет. Вмешательство человека отделено от последующих самостоятельных проверок.

Это переиспользуемый UI навык, а не миссия онборда. Запрос человека: научиться открывать инвентарь и полностью взаимодействовать с ним. Один отдельный исполнитель владеет Unity; координатор готовит знания без MCP. При повторе загружать эту карточку и только нужные ограничения, не всю память.

## Семантическая карта из исходников

- В игровом HUD вход находится по компоненту `UIHudInterfaceButtonBackpack` (`Type=Backpack`). Он вызывает `UIBackpackInterfaceStarter.Open("InventoryInfoNEW")`. Альтернативный уже открытый root-nav использует `BackpackRootTabHandler`.
- Перед открытием и при закрытии может появиться interstitial. Наличие рекламы не является готовностью инвентаря. Известная заглушка LevelPlay закрывается её Close; наградную рекламу/покупку не запускать как способ доступа к инвентарю.
- `BackpackManager` присоединяет общую панель `DragInventoryExtendable` и вторую панель `InventoryInfoNEW`. В рюкзаке есть и другие контексты: Craft/станция/контейнер/LongUnlock; не считать их одним окном инвентаря.
- Слоты наблюдаются через `UIDragItemCell.Cell`, `.Item`, `.Storage`; актуальный индекс хранится в `_index`. Выбирать цель по контейнеру, ID/типу предмета и текущему слоту. Геометрия вычисляется заново по реальному UI, координаты экрана не сохраняются в знании.
- `SelectionManager.Selected`, `.SelectedIndex`, `.SelectedContainer.Storage` описывают текущий выбор. Читать их можно; программный вызов Select/Put/OnDrag не доказывает работу пользовательского UI.
- Описание по удержанию обслуживает `CraftObjectDescription`: down запоминает `Time.time`, а `Update` показывает описание после `_longTapTime` (в исходнике 0.35 с). Up отменяет ожидание; BeginDrag отменяет его и скрывает описание. Обычный pointerClick этого компонента пустой. Для проверки нужен правильный hit/handler предмета, реальные кадры во время удержания и снимок до отпускания; прямой Show/Click не проверяет зажатие.
- `ActionWithItemsView` содержит Use, Split, Remove, Sort. Remove и Sort показываются взаимоисключающе: доступность Remove скрывает Sort. Поэтому отсутствие Sort при выборе предмета не означает исчезновение функции.
- Use зависит от класса и контекста: инструменты/оружие/броня/рюкзак экипируются; еда/вода/расходники тратятся; чертежи/записи/скины меняют состояние прогресса; Build запускает размещение. При активном LongUnlock сначала возможно помещение предмета в строительство. Единого безопасного эффекта для всех Use нет.
- Обычные контейнеры создаются по ключам `backpack`, `belt`, `equipment`; фактический runtime UID и регистр брать из снимка. У брони слоты Hat=0, Cape=1, Pants=2, Boots=3. Belt фильтрует допустимые классы; рюкзак имеет специальный слот и ограничения переноса заполненного рюкзака.
- Split допустим для Resource/Consumable с количеством больше 1, вне Belt, при свободной ячейке текущего полного контейнера. `SplitItemView` содержит slider, split/cancel/close; LeftQuantity + RightQuantity должны равняться исходному количеству. Подтверждение помещает часть в первую свободную ячейку, а не обязательно рядом с исходной.
- Вкладки инвентаря соответствуют текущим доступным хранилищам. Нажатие заблокированной вкладки может открыть покупку расширения; это не обычный переход на доступную вкладку.
- Sort работает по текущей вкладке с подключённым рюкзаком, чередует направление и может объединять одинаковые стаки. Проверять количество и прочность, а не только перестановку иконок.
- Remove сначала открывает Yes/No (`RemoveConstruction`); удаление происходит после Yes. Проверка открытия и отмены подтверждения не доказывает удаление предмета.

## Контракт обучения и результата

Группы: вход/выход; выбор и описание; доступные вкладки; перенос и обмен слотов; split/merge; экипировка/снятие; сортировка; контекстное Use; Remove и его отмена. Для каждой группы отдельно фиксировать источник, предусловия, выполненный реальный ввод и результат. Не объявлять «полностью освоен» по одному открытию.

До операций сохранить выбранную вкладку, контейнеры и непустые ячейки: UID, количество, прочность, доступность. Для переноса/split/merge/экипировки сумма по UID сохраняется; при возврате проверить исходные слоты/экипировку. Для расхода требуется отдельная ожидаемая дельта и эффект. Sent/открытие окна не заменяют итоговой проверки.

Реальные жесты синхронизировать с кадрами: down → frame → up; drag также включает начало, движение, актуальный hit-test цели и завершение на ней. Не повторять отправленный ввод при неизвестном исходе. После новой неожиданной красной ошибки прекратить ввод и сохранить причину. Прошлые исключения Console не наследуются.

До этого Cancel был подтверждён, reselect/Split вернули доказанное `not_sent_covered` с cover=BG, slider — `not_sent_missing`; Confirm не выполнялся. Новых ошибок Console не было, Trash24 суммарно и прочие предметы/прочность сохранены, cleanup подтверждён. Это ошибка наблюдателя/допуска следующего шага, не обнаруженный дефект игры. Исправление должно делать чтения null-safe и ограниченно ждать исчезновения известного перекрытия прежде чем повторить доказанно неотправленное действие; не выполнять зависимые шаги после not_sent.
