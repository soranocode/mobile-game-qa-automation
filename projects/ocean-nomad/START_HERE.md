# Ocean Nomad: пилот QA с Codex

**Сейчас — только подготовка.** Начни с [среды](../../docs/ENVIRONMENT.md), [плана](PLAN.md) и [передачи контекста Cursor](../../docs/CURSOR_HANDOFF.md). Команды подключения и работы с телефоном ниже предназначены для будущего практического этапа. По просьбе пользователя сейчас их не запускаем. Все команды ниже выполняются из корня репозитория.

Это локальный мост между Android-телефоном и Codex: скриншоты → решение ИИ → касание или свайп → новый скриншот → проверка результата. Исходники игры, Unity Editor и API-ключ не нужны. Python вызывает установленный ADB; Codex анализирует локальные файлы в этом чате.

**Текущий статус:** подготовлен инструмент. На Ocean Nomad он ещё не проверен: телефон при подготовке не был подключён. Прохождение миссий, устойчивость и экономия времени пока не измерены. Это интерактивный пилот в текущем чате; самостоятельный запуск по расписанию здесь не настроен.

## 1. Подключение

На Android включи режим разработчика и «Отладку по USB». Подключи разблокированный телефон кабелем к этому компьютеру и разреши отладку для компьютера на экране телефона.

В PowerShell, из корня репозитория после подготовки `.venv`:

```powershell
& .\.venv\Scripts\python.exe .\tools\android\android_qa.py devices
```

Рядом с телефоном должно быть `device`. `unauthorized` означает, что нужно подтвердить отладку на телефоне. Если подключено несколько устройств, добавляй `--serial СЕРИЙНЫЙ_НОМЕР` перед названием команды.

На первом компьютере при подготовке были Python 3.12 и ADB. На другом ПК установи Python 3.10+ и [официальные Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools).

## 2. Найти пакет и начать с одной миссии

Открой Ocean Nomad на телефоне. Список установленных сторонних приложений:

```powershell
& .\.venv\Scripts\python.exe .\tools\android\android_qa.py packages
```

Название пакета нельзя угадывать по названию игры. Нужен реальный идентификатор установленного билда.

Подготовь начало одной конкретной онбординг-миссии. Запиши текст задания и видимый признак завершения: например, смена текста задания или экран награды. Не считай появление нужного предмета достаточным признаком завершения, если это не следует из задания.

Для повторов нужен одинаковый старт: тестовый аккаунт, слот или предусмотренный игрой способ начать обучение. Сброс данных приложения инструмент не выполняет. Если начало обучения нельзя восстановить без разработчика, это ограничение пилота, которое следует явно зафиксировать.

Пример команды: замени все четыре значения в угловых скобках, в том числе условный пакет.

```powershell
& .\.venv\Scripts\python.exe .\tools\android\android_qa.py init --session .\runs\ocean-nomad\attempt-01 --package "<пакет_игры>" --build-label "<версия_билда>" --initial-state "<аккаунт или слот, начало миссии>" --mission "<текст миссии и видимый признак её завершения>"
```

Команда сохраняет первый скриншот и метаданные. Она требует, чтобы игра уже была на переднем плане. Каждому повтору — отдельная папка `attempt-02` и т. д. Не запускай несколько команд одновременно в одной сессии.

## 3. Подключить Codex к прохождению

После создания сессии отправь в этот чат текст из [PROMPT_FOR_CODEX.md](PROMPT_FOR_CODEX.md), указав абсолютный путь к папке сессии. Codex сможет читать скриншоты, вызывать мост и записывать шаги. Отдельный платный API для этого способа не требуется; действуют лимиты текущего продукта.

Один шаг — одно действие и проверка нового изображения. Начинаем с одной миссии на одном устройстве. При неопределённости фиксируем NEEDS_REVIEW и останавливаемся на этом участке.

Ниже синтаксис команд. Координаты в примерах условные: сначала нужно посмотреть реальный скриншот. X растёт слева направо, Y сверху вниз; диапазон 0–1. Например, 0.5 / 0.5 означает центр экрана.

```powershell
& .\.venv\Scripts\python.exe .\tools\android\android_qa.py observe --session .\runs\ocean-nomad\attempt-01 --note "Перед следующим действием"
& .\.venv\Scripts\python.exe .\tools\android\android_qa.py tap --session .\runs\ocean-nomad\attempt-01 --x 0.5 --y 0.5 --expect "Описать ожидаемое видимое изменение"
& .\.venv\Scripts\python.exe .\tools\android\android_qa.py swipe --session .\runs\ocean-nomad\attempt-01 --x1 0.2 --y1 0.8 --x2 0.2 --y2 0.6 --duration 0.7 --expect "Описать ожидаемое видимое изменение"
```

После каждого касания/свайпа есть скриншоты до и после, состояние процесса и доступные логи. `--wait` задаёт паузу после действия от 0 до 10 секунд. Если загрузка ещё идёт, сделай новое наблюдение позже; не повторяй касание автоматически.

Команда не отправит ввод, если игра не на переднем плане или после последнего наблюдения изменилось разрешение/ориентация экрана. Это ограниченная проверка: она не распознаёт игровые диалоги и не гарантирует, что координата указывает на нужную кнопку.

## 4. Проверка результата

`runs/ocean-nomad/attempt-01/session.json` содержит время и последовательность событий. `REVIEW.md` в папке сессии содержит пути к доказательствам. Каждый ввод изначально имеет результат **NEEDS_REVIEW**: успешное выполнение команды ADB не доказывает прохождение миссии.

Человек или агент может записать отдельную оценку с указанием источника, обоснования и существующего скриншота этой сессии:

```powershell
& .\.venv\Scripts\python.exe .\tools\android\android_qa.py checkpoint --session .\runs\ocean-nomad\attempt-01 --result NEEDS_REVIEW --source human --note "Пока недостаточно данных о завершении миссии" --evidence "<имя_существующего_скриншота.png>"
```

PASS/FAIL в checkpoint — оценка указанного человека/агента, а не встроенная проверка игры. Для итогового отчёта нужна ручная сверка завершения задания. Отсутствие ошибок в логах тоже не означает PASS.

Логи — ограниченные снимки последних сообщений PID игры; они могут включать сообщения до запуска сессии и пропустить сбой. При смене PID или завершении процесса часть данных может отсутствовать. FPS, память, ANR и качество физики этот прототип автоматически не оценивает.

## Границы первого примера

- Одинарные касания и свайпы. Одновременное управление движением и камерой пока не поддерживается.
- В 3D одинаковый свайп может дать разное положение камеры/персонажа. После каждого действия нужен новый осмотр; координаты относительно экрана не обеспечивают одинаковый игровой результат.
- ИИ может неверно понять скриншот. Подозрение на визуальный дефект требует подтверждения, особенно в движении и при работе физики.
- Инструмент сохраняет файлы локально. При просмотре скриншотов и логов через Codex их содержимое обрабатывает подключённая модель.
- Неизвестные экраны, покупки, реклама, согласия, привязка аккаунта и удаление прогресса не входят в сценарий.

После повторяемого прохождения одной миссии можно добавить распознавание устойчивых элементов через [Airtest](https://airtest.doc.io.netease.com/en/tutorial/1_quick_start_guide/). Для доступа к дереву UI Unity через Poco потребуется интеграция SDK в игру. [Unity MCP](https://github.com/CoplayDev/unity-mcp) работает через Unity Editor и требует другого доступа, чем готовый APK.
